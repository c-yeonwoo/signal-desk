# 후보를 먼저 보는 투자 작업대

2026-10-31 소유자는 첫 과업으로 새 매수 후보 확인을 선택하고, 오늘·종목을 잇는 두 메뉴 구조와 종목 상세 정리를 승인했다. PC·모바일에서 확인 가능한 실제 프론트엔드를 구현한다.

**THESIS:** 후보 → 선정 이유와 주의점 → 기존 전체 차트 → 원문과 계산 근거.

**OWN-WORLD:** 기존 Pretendard·중성 배경·indigo 조작 색과 의미별 가격 색을 계승한다. 장식 이미지·새 서체·일상적인 LLM 요약 호출을 추가하지 않는다.

**STORY:** 오늘의 국내/해외/관심 → 상위 후보 최대3개와 전체 후보 → 종목 상세 → 내 투자 또는 전체 종목 탐색. 상위3개는 표시량이며 엔진의 후보 수나 순위를 바꾸지 않는다.

**FIRST VIEWPORT:** 가격/운영 상태와 후보를 먼저 읽는다. 시장 정보는 한 줄과 접힌 근거로 남긴다. 모바일은 목록과 상세를 왕복하고 가격·판정 시각, 손실 기록을 생략하지 않는다.

**FORM:** 합의된 구조의 코드 중심 구현이다. 이미지 시안이나 예시 가격을 운영 데이터로 전환하지 않는다. 실제 UI에 합성 API를 붙인 로컬 검수 화면은 노란 예시 표시로 운영과 구분한다.

**FINISH:** PC1440·모바일390의 첫 화면과 상세, 가격 지연·장외·매수 보류·실패 상태를 확인한다. 독립 코드 리뷰·마감 리뷰·정확한 PR HEAD CI 후 머지하며, 배포 확인과 사용자의 실제 피드백은 별도다.

## 데이터와 상태 계약

- `/api/signals`의 최종 판정과 기존 목록 정렬을 사용한다. HOLD·차단·자료부족·무효 가격으로 빈 후보 자리를 채우지 않는다.
- 현재 후보는 서버의 `current_decision_eligible=true`와 프론트의 만료 검사를 함께 통과해야 한다. 종가 참고는 `close_reference_only`로 명시된 행만 표시한다.
- 가격의 서버 수신 시각은 공급자 마지막 체결 시각 인증이 아니다. 카드에 성공 확률이나 검증된 수익률을 추가하지 않는다.
- 운영 보류는 기존 레퍼런스 봇 상태 API의 `buy_paused`를 읽는다. 조회 실패는 미확인이며 false로 취급하지 않는다. 설정을 바꾸거나 LLM·주문을 실행하지 않는다.
- 운영 상태 응답이 늦어도 종목 응답을 먼저 표시한다. 시장 전환 전 응답을 버리고 재렌더 시 키보드 포커스를 보존한다.
- 후보 화면의 캐시는 전체 목록의 관심종목 초기화를 건너뛰게 만들지 않는다.
- 거래일 정합성과 원천 시각의 의미 인증, 선정 성과는 디자인 완료와 다른 검증이다.

## 이번 배포 범위

앱 셸·오늘 후보·전체 종목 진입·종목 상세의 기본 정보량을 정리한다. 내 투자 내부의 계좌/분석 입력 작업 분리, 모의투자 성과 화면 재구성, 관리자 내부 전체 개편은 후속이다. 엔진·매매 규칙·연구 표본·Railway·Paperclip은 변경하지 않는다.
