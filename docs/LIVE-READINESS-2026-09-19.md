# 신뢰도 보강과 실전 계좌 연동 — 2026-09-19

## 이번 배포의 경계

실전 계좌를 **조회하고 주문 여력을 검사하는 연결 기반**이다. 실주문 활성화 배포가 아니다.
기존 페이퍼 봇/레퍼런스 장부는 유지하며 실계좌 주문과 연결하지 않는다.
복수 계좌·환율·계좌별 세금 최적화는 범위 밖이다. 초기 어댑터는 기존 KIS 국내 현물 코드를 사용했다.

- `KIS_ENV=demo|real`만 허용한다. `prod` 등 오타는 실패 처리한다.
- `real`의 주문 함수와 저수준 비-GET 전송은 모두 차단한다.
- `ALLOW_REAL_ORDERS=true`도 이 빌드의 차단을 해제하지 않는다.
- `/api/live/orders` 같은 주문 전송 API는 없다.
- 계좌 조회는 로그인 이메일이 `KIS_ACCOUNT_OWNER`와 일치해야 한다. 관리자 권한만으로 우회할 수 없다.
- 실제 인증정보/계좌 조회/주문을 사용한 검증은 수행하지 않았다. 모의 응답과 합성 데이터로 검증했다.

## 수정한 신뢰성 결함

1. 메타 모델은 종목별 배열 위치 대신 공통 날짜 축으로 분할하고, 같은 세션은 같은 fold에 둔다.
   진입은 기존 accuracy 규약과 같이 신호 다음 거래일 종가로 변경했다. 과거 shadow 수치는 새 규약으로
   재평가해야 하며, 이것만으로 정책 승격을 허용하지 않는다.
2. 리스크 패리티 반복식을 convex risk-budget 좌표하강으로 바꾸고 잔차를 확인한다.
   수렴하지 않은 결과는 반환하지 않는다. 이후 cap 적용은 별도 단계이므로 최종 비중을 순수 ERC 해라 주장하지 않는다.
3. 고상관 묶음 한도를 목표배분과 최종 계획 검사에 포함한다.
4. 신규 후보와 기존 보유는 `portfolio_decision.decide`에서 함께 배분하고 하나의 현금 원장을 사용한다.
   후보 표의 금액은 동일 행동계획의 일부이며 독립적인 추가 지출안이 아니다.
5. 보유 평가액/이력 결손, 부분 상관 결손, 상수 가격, 비유한 값, 날짜 중복/불일치에서 보류한다.
   후보 상관과 변동성은 최근 60개 수익률을 사용한다. 최종 기준일 일치는 절대 신선도 인증을 의미하지 않는다.
6. BUY 확인이 없는 확대는 차단한다. 최소 현금은 비용을 내기 전에 예약한다.
   비용과 정수 수량 반영 후 종목·섹터·묶음·현금 한도를 다시 검사하며 위반 계획은 노출하지 않는다.
7. LLM 비스트리밍 도구 호출의 미정의 `purpose`로 성공 응답/사용량이 유실되는 문제를 수정한다.
8. 신규 권고에 완전한 비용 가정을 저장하고 사후 청산 계산에 재사용한다.
   비용 가정이 없는 과거 권고의 순수익은 미확인으로 표시하며 현재 설정으로 추측하지 않는다.
   화면의 매수는 비용 후 수익, 매도는 비용 미반영 가격하락 회피 지표로 구분한다.

## 연결 화면과 API

실보유 포트폴리오 영역의 접이식 **KIS 실전 연결 준비** 카드:

- 연결 상태: `GET /api/live/status`
- 잔고·당일 KRX 주문 조회: `POST /api/live/account`
- 지정가 주문 여력 사전조회: `POST /api/live/preflight`

서버 환경변수(값을 문서/채팅/커밋에 넣지 않는다):

`KIS_APP_KEY`, `KIS_APP_SECRET`, `KIS_ACCOUNT_NO`, `KIS_ACCOUNT_PRODUCT_CD`,
`KIS_ENV`, `KIS_ACCOUNT_OWNER`.

소유자가 서버의 비밀 설정으로 직접 구성한 뒤 조회 화면에서 확인한다. real 전환은 조회만 허용한다.
주문 가능 금액은 예수금/순자산 역산이 아니라 KIS의 `nrcvb_buy_amt`, `nrcvb_buy_qty`를 사용한다.
매도는 보유 수량과 매도가능 수량을 구분한다. 매도가능 수량을 받지 못하면 보류한다.

토큰은 환경·앱키·키 교체·계좌별로 분리하고 파일 권한 0600으로 저장한다.
기존 무구분 `kis_token.json`은 삭제하지 않지만 재사용하지 않는다. 첫 조회에서는 새 토큰 발급이 필요할 수 있다.
현재 발급 락은 단일 프로세스용이다. 다중 프로세스 운영 전에 분산 토큰 발급 조정이 필요하다.

잔고/주문은 연속조회가 모두 끝나야 완전한 응답이다. 뒷 페이지 실패·반복 커서·최대 페이지 초과는 실패한다.
미체결·부분체결·불명 주문이 있으면 추가 주문 여력 판정을 보류한다. 실패를 빈 계좌나 주문 0건으로 바꾸지 않는다.
동시 수동 계좌 조회는 429로 거절한다. 이는 전체 증권사 호출의 전역 rate limiter를 대체하지 않는다.

`broker_checks_passed=true`는 **조회한 계좌의 여력**만 통과한 상태다. 항상 `ready=false`,
`order_transmission_enabled=false`이며 투자정책/주문 승인을 뜻하지 않는다.
시세 신선도·휴장/세션·호가 단위·주문 한도·손실 한도·권고 만료를 인증하지 않았기 때문이다.

공식 규약 확인 출처:

- [한국투자증권 Open API](https://github.com/koreainvestment/open-trading-api)
- [매수가능 조회](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_psbl_order/inquire_psbl_order.py)
- [일별 주문체결 조회](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_daily_ccld/inquire_daily_ccld.py)

## 실주문 전에 남은 작업 (순서 유지)

1. **공통 시점 스냅샷**: 확정봉/호가 분리, 거래소 캘린더, 정보 이용 가능 시각, 데이터/정책 버전,
   권고 시각과 체결 가능 시각, 전체 데이터 재현용 아티팩트. 현재 결정 해시는 전체 데이터 원장을 대체하지 않는다.
2. **포트폴리오 반사실 원장**: 동일 초기 자산에서 유지/단순 정책/신규 정책의 비용 후 NAV 경로 비교.
   현재 개별 권고 1/5/20일 결과는 이 검증이 아니다. 일별 스냅샷 중복의 원자성·시장별 마감 작업도 보강한다.
3. **주문 수명주기 원장**: 결정 ID+계좌+주문 intent의 고유키, 현금/수량 예약, 제출 전 영속화,
   접수·부분체결·완료·취소·거절·상태 불명 전이. 타임아웃은 실패가 아니라 UNKNOWN으로 유지하고
   재전송 전 반드시 증권사 원장과 대조한다. exactly-once 체결을 주장하지 않는다.
4. **실행 전 게이트**: 소유자 확인, 증권사 선택, 종목/시장/세션, 최신 호가, 지정가/추격 허용폭,
   주문당/일별 총액, 위험 증가와 위험 축소 구분, 미체결 예약, 일손실 제한, 비상 정지.
   한도는 사용자가 정하고 키/설정 변경만으로 활성화되지 않게 한다.
5. **알림 배송 원장**: 사용자/수신자별 상태, 작업 점유, 부분 실패 재시도, 권고 만료/취소,
   설명 LLM 실패 시 결정론적 위험 안내. 현재 공용 텔레그램 outbox를 개인 실계좌 알림에 그대로 쓰지 않는다.
6. **승격**: 정합성·장애/재시작·모의 체결 검증, 미관측 OOS, 비용/지연 스트레스, 사용자 검토 이후
   제한된 사용자 승인 주문 경로를 별도로 설계한다. 자동 주문 활성화와 실제 거래는 이번 작업에 포함되지 않는다.

추가 보류: LLM 동시 호출 예산 예약/정산, 실측 성공확률 보정, 기대수익 기반 신규편입 최적화,
스케줄러/작업자 분리. 현재 통합 배분은 위험배분 기준 정책이지 수익률 최적 정책이 아니다.

## 검증 원칙

테스트 통과는 수익성 입증이 아니다. 합성 반례를 회귀 검사에 추가하고, 실제 운영/증권사 응답은 별도 확인한다.
화면은 합성 응답을 제공하는 격리 서버에서 390px/1512px 레이아웃·조회 동작·콘솔 오류를 확인한다.
실계좌 인증정보를 로드하는 앱 서버나 실주문 API를 검증 목적으로 실행하지 않는다.
