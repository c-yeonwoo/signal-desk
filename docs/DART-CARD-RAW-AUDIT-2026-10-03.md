# 국내 재무 카드–보존 원문 대조

작성: 2026-10-03 · 2026-10-06 운영 실측 추가 · 상태: **공식 공시 수치 대조 완료, 재배포 보존 확인 대기**

관리자 › 운영 상태 › 상세 데이터 진단의 `국내 재무 카드·보존 원문 대조` 버튼은 외부 사이트에 접속하지 않는다. **첫 운영 원문 수집 전 고정한 선정 규칙:** 보존된 DART API 응답의 법인코드를 정렬하고, 전년 동종 보고서가 있어 비교 카드가 성립하는 첫 2개를 **원문 금액의 일치·불일치 결과를 보기 전에** 고른다. 비교 카드가 없는 법인은 제외 이유와 함께 표시한다. 보존 무결성 오류가 먼저 나오면 뒤의 법인으로 대체하지 않고 검사를 중단한다. 선정된 카드가 불일치해도 표본에서 빼지 않는다. 각 법인의 같은 보고서·연도·연결 기준에서 화면 카드의 매출액·영업이익·영업현금흐름·재고자산을 원문 `thstrm_amount`와 대조한다. 계정 ID, 재무제표 구분, 통화, 접수번호, 전년/당년 금액, 증감률, DART 원문 링크가 모두 맞을 때만 `일치`다. 한 항목이라도 모호하거나 보존 해시가 깨지면 기권/오류로 표시하며 성공으로 세지 않는다.

이 검사는 **저장된 API 응답과 서비스 계산의 정합성**이다. DART 웹사이트 공시 원문의 진위·수정 여부, 실제 공개시각, 종목 수익률을 증명하지 않는다. 두 실측 카드가 모두 일치해도 운영자가 각 접수번호의 공식 원문을 열어 금액·단위·보고기간을 확인하고, 배포 이후 보존본이 남는지 확인해야 데이터 확장 4단계의 원문 대조 관문을 완료로 판정한다. 합성 테스트의 숫자는 운영 증거가 아니다.

## 2026-10-06 운영 첫 표본

국내 정상 마감 뒤 관리자 › 운영 상태에서 DART 최근 30일 요청 **8회**, 성공 **8회**, 자료 없음·실패 **각 0회**, 응답 **0.9 MiB**, 보존 원문 **8건**을 확인했다. 첫 관측 ID는 `42ba0ae054c32c1ed3dde1d6eb97ec9c986ce5bdc6c3f551d0580993d66a7157`, 첫 이용 가능 시각은 `2026-10-06T06:54:03.343081+00:00`이다. 감사 버튼은 관측 법인 4개 중 사전 고정 규칙에 따라 첫 비교 가능 법인 `00126380`, `00164742`를 선정했고, 두 법인 모두 저장된 API 응답과 카드 계산이 일치했다. 나머지 두 법인은 정해진 2개 표본 밖이며, 제외 사유가 있는 법인을 건너뛰어 표본을 고르지 않았다.

공식 [삼성전자 반기보고서(접수번호 20260814003699)](https://dart.fss.or.kr/dsaf001/main.do?rcpNo=20260814003699)와 [현대자동차 반기보고서(접수번호 20260814003521)](https://dart.fss.or.kr/dsaf001/main.do?rcpNo=20260814003521)의 연결재무제표를 별도로 열어 아래 금액을 확인했다. 원문 표의 단위는 **백만원**, 앱 감사 수치의 단위는 **원**이므로 표의 각 수치에 1,000,000을 곱하면 앱 감사 수치가 된다. 비교 연도는 2025→2026이다.

2026년 매출·영업이익은 각 2026년 보고서의 3개월 열, 영업현금흐름은 2026-01-01~06-30 열, 재고는 2026-06-30 열과 대조했다. 2025년 매출·이익·현금흐름은 같은 2026년 보고서의 전년 비교 열과 대조했다. 2025년 6월 말 재고는 별도의 공식 [삼성전자 2025년 반기보고서](https://kind.krx.co.kr/external/2025/08/14/002493/20250814007611/11012.htm)와 [현대자동차 2025년 반기보고서](https://kind.krx.co.kr/external/2025/08/14/003182/20250814009937/11012.htm)의 연결 재무상태표로 대조했다. KRX의 2025년 HTML 경로는 DART의 2026년 접수번호와 서로 다른 문서 ID이며, 원문 공개시각을 인증한다는 뜻은 아니다.

현재 감사 UI는 `2025→2026`만 먼저 보여 주므로 손익 3개월·현금흐름 6개월·재고 시점의 차이가 한눈에 드러나지 않는다. 기간 라벨을 후속 사용성 개선 항목으로 남긴다. **재배포 전후 동일 관측 ID·건수 확인은 아직 미완료**이므로 2.0 장부의 운영 보존·원문 대조 점수는 이 관측만으로 더하지 않는다.

[OpenDART 전체 재무제표 개발가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020)는 **분·반기** (포괄)손익계산서 `thstrm_amount`를 3개월 금액, `thstrm_add_amount`를 당기누적금액으로 설명한다. 사업보고서(`11011`)에는 이 3개월 규칙을 적용하지 않는다. 따라서 카드의 매출·영업이익은 분·반기에만 3개월, 사업보고서에는 보고기간 당기금액으로 고른다. 현금흐름은 보고기간 금액, 재고는 보고기말 잔액으로 분리해 표기한다. API의 동일 사업연도/보고서 코드는 실제 회계기간 시작·종료일을 인증하지 않으므로, 회계연도 변경 등은 공식 공시 원문을 열어 별도로 확인해야 한다.
