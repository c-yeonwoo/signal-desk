# 합병 정산: 사용 목적과 표시 정밀도를 분리한다

2026-10-13 · Astra 설계 결정 · 기준 `34fd108` (#701). **설계 확정, 아래 후속 구현은 미완료.**

[정산 계약 v2](RESEARCH-SETTLEMENT-CONTRACT-V2-2026-10-12.md)의 보완이다. 기존 원문·동결 JSON·1,488행의 partial, 등록 연구·주문 잠금을 바꾸지 않는다.

## 1. 병목을 바로잡는다

모의 백테스트에 개인 계좌 입고·입금증은 필요하지 않다는 v2 결정을 유지한다. 최근 원문 검수 보고의 공통 결손 문구에 `actual holder share delivery`가 섞여 있어, 공개 조건을 이용한 모의 평가까지 기다려야 하는 것처럼 읽힐 여지가 있었다.

현재 원문 감사 스크립트는 수익률을 계산하지 않는다. 개인 입고 필드 하나가 시뮬레이터 실행을 막는 런타임 결함을 발견했다는 뜻은 아니다. **보고서의 사용 목적과 후속 계산 계약을 명확히 하는 작업**이다. 실제 계좌 관련 false/null은 삭제하지 않고 별도 상태로 남긴다.

| 상태 | 확인할 것 | 개인 계좌 증빙 |
|---|---|---|
| `source_review_status` | 선언한 원천·사건·정정 범위의 검수 종료 | 불필요 |
| `simulated_entitlement_status` | 모의 보유 경로와 공식 권리 조건으로 계산 가능한가 | 불필요 |
| `economic_valuation_status` | 고정 평가일의 가격·권리 가치와 범위가 충분한가 | 불필요 |
| `simulated_cash_availability_status` | 확인된 지급 또는 명시한 지급 가정에 따른 모의 주문 가능 현금 | 불필요 |
| `account_realized_status` | 실제 입출고·입금·체결·비용을 재현했는가 | 필요 |

`missing_by_purpose`에 부족한 사실·근거 ID를 따로 둔다. 특정 사건 계산 가능과 기간 전체 총수익 인증은 별개다. 기존 감사 JSON을 고쳐 complete로 만들지 않고 v2 파생 보고서를 만든다.

## 3. 비율·금액 계산 계약

비율은 다음을 구별한다. 모든 수치는 Decimal 또는 유리수로 처리한다.

- `exact_contractual_decimal`: 최종 계약에서 정확 조건으로 확정된 유한소수.
- `derived_exact_rational`: 정확한 분자·분모와 계약상 산식이 모두 확인된 경우만.
- `displayed_with_documented_rounding`: 공식 표시 변환에 따라 열린/닫힌 끝점을 포함한 구간을 도출.
- `displayed_precision_unknown`: ‘7자리 표시’만 있고 변환은 모름. 임의 ±0.5×10⁻⁷ 또는 ±10⁻⁷ 금지.

공시상 교부조건은 `declared_delivery_ratio`로 별도 저장하며 위 정밀도·최종성 상태와 혼동하지 않는다. `reported_terms_scenario`는 그 숫자를 가정한 계산일 뿐 실제 오차 범위나 인증 총수익이 아니다.

권리 적격 수량 n, 비율 r, 정수 신주 q=floor(nr), 단주 f=nr−q, 공식 단주 기준 가격 P_l, 평가일 신주 가격 P_t라면, 반올림 전 권리 가치는 `V(r,T)=q×P_t+f×P_l`이다. 단주 가격이 아직 결정되지 않았다면 미래 P_l을 과거 판단/NAV에 넣지 않는다. 사후 결과 라벨은 별도 `ex_post_outcome`으로만 계산한다.

공식 근거가 있는 r 구간이 정수 경계를 넘으면 각 q와 f를 **같은 r의 짝**으로 평가한다. 서로 불가능한 신주 최대·단주 최대를 조합하지 않는다. P_t와 P_l이 다르면 구간 끝값뿐 아니라 정수 경계 및 좌우 극한을 검사한다. 최솟값/최댓값과 미달성 하한/상한을 구별한다.

원화 지급 반올림 규칙이 없으면 `unrounded_gross_entitlement`와 명시적 가정 시나리오까지만 낸다. 자동 ‘오차 1원 이하’나 확정 지급액 주장은 금지한다. 미수권리→현금 이전은 NAV에 중복 가산하지 않는다. 공식 예정일과 실제 확인 지급일을 구분하고, 지급시각이 없는 확인 지급은 다음 정규 세션부터 사용한다.

## 4. Sol high 구현 순서와 인수시험

3. 연구 평가 원장 연결: 신주 거래 가능 시점, 미수권리, 사용 가능 현금과 평가액 분리. 기간 전체 인증은 기존 v2 관문 유지.
4. 고정 7개 개발 창에 파생 보고서 생성. 전체 분모·결손·가정 유지. 연구 결과를 운영 점수/주문에 전달하지 않음.

필수 시험:

- 개인 계좌 증빙 없이 모의 평가 가능; 실제 계좌 수익은 null 유지.
- 정밀도 불명 입력에 자동 비율구간 생성 거부; 표 가격 나눗셈으로 교부조건 덮어쓰기 거부.
- 합성 `n=100`, `r∈[0.09999,0.10001]`, `P_l=100`, `P_t=50`: 양 끝은 549.9/500.1이지만 내부 r=0.1에서 최소 500; 상한 550은 미달성임을 표시.

- 상장/가용 이전 매도 없음, 미래 상장 종가의 과거 복사 없음, 정정 중복 지급 없음.
