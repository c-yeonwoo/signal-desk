# 검증 시스템 — 판정은 기계, 가설은 에이전트 (2026-07-26)

## 왜 에이전트 상호검증이 아닌가

하네스를 만들며 세 번 틀렸다. 매수 0건인 기간에 거래비용을 물렸고, 점수 동점을 시총 순으로
정렬해 "점수 없으면 대형주 매수"가 몰래 섞였고, 대조군만 위상 평균을 안 해 전략이 이겨 보였다.

세 번 다 잡아낸 건 리뷰가 아니라 **대조군**이었다. 같은 계열 모델끼리 검증시키면 같은 사각지대를
공유하고 서로 동의하는 쪽으로 수렴한다 — "방법론이 타당해 보입니다"는 버그가 세 개 있어도 나오는
문장이다. 그래서 **판정 권한은 기계에만** 준다.

| 층 | 무엇 | 권한 |
|---|---|---|
| 0 | CI (`.github/workflows/ci.yml`) | **머지를 막는다** |
| 1 | 레드팀 스위트 (`tests/test_redteam.py`) | **판정한다** |
| 2 | 가설 생성기 (`src/signal_desk/audit.py`) | 질문만 한다. 아무것도 못 바꾼다 |

## 0층 — CI

테스트 657개가 있어도 푸시를 막는 게 없으면 전부 권고문이다. PR·main 푸시에서 `pytest` 전체와
레드팀 스위트를 따로 한 번 더 돌린다(실패 시 어느 층이 무너졌는지 로그에서 바로 보이게).

## 1층 — 레드팀: 반증 가능한 검사만

| 검사 | 무엇을 잡나 | 실패하면 |
|---|---|---|
| **셔플(누수)** | 점수와 수익률의 짝을 어긋나게 해도 판별력이 남는가 | 점수가 미래를 보고 있다 |
| **음성 대조군** | 랜덤워크 시장에서 엣지를 만들어내는가 | 도구가 없는 엣지를 발명한다 |
| **양성 대조군** | 엣지가 실재하는 시장에서 잡아내는가 | 도구 고장 — 다른 모든 `판정 불가`가 무의미 |
| **미래 불변성** | t 이후 가격을 바꿔도 t 시점 출력이 같은가 | replay 경로에 룩어헤드 |
| **base rate 동반** | 정밀도류 비율에 기준선·리프트·신뢰구간이 붙는가 | 절대값만 보고 매번 속는다 |
| **표본·커버리지 차단** | 못 믿을 숫자에 판정을 내리는가 | 이름과 다른 전략을 인증한다 |

양성 대조군이 특히 중요하다. 검사를 촘촘히 하면 **아무것도 통과 못 하게 만들기 쉽고**, 그러면
`판정 불가`가 정보가 아니라 고장 신호가 된다. 실제로 커버리지 차단을 넣자마자 양성 대조군이
깨졌다 — 그때 알았다. 기술 팩터는 RSI 기반이라 **꾸준히 오르는 종목을 오히려 피한다**(과매수).
"오르는 종목이 있는 시장"은 이 팩터의 양성 대조군이 될 수 없어서, 종목마다 위상이 다른 진동장
(전방 5일 IC +0.31)으로 바꿨다. 양성 대조군은 **그 팩터가 원래 잘해야 하는 시장**이어야 한다.

## 2층 — 가설 생성기: 판정권 없는 LLM

`sigdesk` 관리자 → 엔진 탭 → "감사 가설". 계측 스냅샷(엔진 설정·데이터 건강·정확도·advisor
shadow)을 읽고 **"이 숫자가 틀렸다면 왜일까"** 목록만 낸다.

제약을 코드와 프롬프트 양쪽에 건다.

- **반증 방법(`falsifier`)이 없으면 저장하지 않는다.** "표본이 더 필요합니다"는 영원히 참이라
  아무것도 막지 못한다.
- 개선안·파라미터 조정 제안 금지. 이미 CI가 막고 있는 항목은 프롬프트에 명시해 중복 지적을 뺀다.
- id를 내용 해시로 만들어 같은 지적이 매주 쌓이지 않게 한다.
- 상태 전환(`promoted`/`dismissed`)은 사람만. 승격은 **1층 테스트로 옮겼다는 뜻**이다.
- 키가 없으면 조용히 비활성(기존 shadow들과 같은 규약). 엔진·봇에 아무 영향 없음은 테스트로 못박음
  (`test_audit_cannot_change_engine_config`).

응답이 `max_tokens`에서 잘리는 건 예외가 아니라 기본값에 가깝다. 통째로 버리면 멀쩡한 앞쪽
가설까지 사라지고 화면엔 "응답 없음"만 남으므로, 중괄호 균형을 세며 **완결된 항목만** 건진다.

## 첫 실행에서 실제로 나온 것

가설 5건 중 2건이 진짜였고, 그중 하나는 **1층 검사로 승격**됐다.

> `coverage.rows=2000`인데 `tickers_matched=0`, `matured_primary=0` — 조인이 통째로 실패한 것
> 아닌가?

기계로 확인해보니 티커 조인은 멀쩡했고(200/200 교집합), 진짜 원인은 다른 데 있었다.
**시세 캐시가 2026-07-03에서 멈춘 채 시그널만 07-24까지 쌓였다.** 시세가 시그널보다 과거라
어떤 신호도 성숙할 수 없는 상태였는데, 화면에는 "track record 누적 중"으로만 보였다.

가설이 지목한 원인(티커 포맷 불일치)은 틀렸지만 **지목한 이상 자체는 옳았다.** 이게 이 층의
쓰임새다 — 어디를 볼지 알려주고, 판정은 기계가 한다.

고친 것: `accuracy.coverage`에 `price_data_to`·`stale_prices`·`blocked_reason`을 넣어
**0의 이유를 말하게** 했다. "아직 안 익음"(정상)과 "수집 중단"(고장)은 대응이 정반대인데
화면에서 똑같이 0으로 보이면 고장을 몇 주씩 못 본다. 승격된 검사는
`test_zero_matured_says_why_it_is_zero`.

## 쓰는 법

```bash
pytest tests/test_redteam.py -q          # 1층 — 도구가 거짓말하는지
sigdesk harness --sweep                  # 판정표(기본값은 판정 불가)
sigdesk harness --shuffle                # 누수 검사 — 여기서 판별력이 나오면 사고
```

가설 생성은 관리자 화면 버튼(`POST /api/audit/run`). 주기 실행은 아직 안 건다 — 큐가 소음이
되면 아무도 안 본다. 큰 변경 뒤에 수동으로 한 번 돌리는 쪽이 지금 규모에 맞다.
