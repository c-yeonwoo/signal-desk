# 공식 근거 수집의 운영 장부

작성: 2026-10-03 · 상태: 코드/테스트 구현, **운영 기간 관측 대기**

- 관심종목 DART, 미국 연준 G.17, 미국 관심종목 SEC 자료는 종목 시그널·주문 경로 밖에서 모은다. `evidence_ops`는 원천별 하루 **첫** 실행 요약을 보존한다. 재시도가 그날의 실패를 성공으로 덮어쓰지 않는다.
- 관리자 운영 화면의 독립 `공식 근거 수집` 카드에서 최근 30일의 실제 요청 수, 성공·자료 없음·실패, 받은 바이트, 마지막 상태를 본다. 전체 `/api/data-health` 진단이 느리거나 실패해도 이 카드는 별도 `/api/admin/evidence-ops`에서 읽는다. 요청이 0이면 실패율은 0%가 아니라 **판정 불가**다. 제공자 요금과 Railway CPU/네트워크 청구액을 확인하지 않았으므로 금액은 `null`이다. 받은 양은 비용의 단서이지 청구액이 아니다.
- DART·SEC의 `raw_changed`는 같은 URL의 이전 관측과 새 원문 SHA-256이 다르다는 뜻이다. 정정 공시나 숫자 수정이라고 확정하지 않는다. G.17의 `revised_periods`는 두 실제 수집본의 겹치는 월 값이 달라진 개수다. 새 월 추가는 수정으로 세지 않는다.
- DART·SEC 요청 전 상태 예약·시작 표시가 실패하면 `state_failure`로 멈추며 `requested`를 올리지 않는다. 요청 후 완료 표시만 실패했다면 실제 수집 결과·응답 바이트를 보존하되 역시 `state_failure`로 알린다. `requested`는 수집기 호출 횟수이지 공급자 청구서의 확정 호출 수가 아니다.
- G.17도 원자적 월간 4회 예약을 사용한다. 시작 표시 전에 상태 저장이 실패하면 예약 슬롯만 소모하고 수집은 0건으로 센다. 완료 표시 실패는 원천 수집 성공/실패와 운영 상태 오류를 분리해 기록한다. 이 장부의 수집기 호출 수를 연준 서버의 확정 처리 건수로 보지 않는다.
- 두 수집기는 원문/정규화 사실을 보존하는 별도 아카이브를 계속 사용한다. 운영 장부는 이 사실을 재구성하지 못하며, 장부 기록 실패가 수집 결과·점수·주문을 바꿀 수 없다. API의 `evidence_activity` 오류는 별도 표시한다.

운영 완료 관문: 최소 여러 수집일의 요청/바이트/실패를 원천 응답과 대조하고, 재배포 후 원문과 운영 장부가 모두 남는지 확인한다. 달력일만 채웠다고 실패율 또는 수익 효과를 입증한 것으로 보지 않는다. 운영 숫자가 검증되기 전에는 2.0 장부의 4단계 8점을 더하지 않는다.

2026-10-04 운영 화면 관측: 기존 전체 데이터 진단은 15초 시간 초과였고 시그널 목록에도 응답 실패가 보였다. 로컬 동일 함수는 1.6초였으므로 운영 지연의 원인을 특정하지 않았다. 독립 카드는 이 장애의 우회 관측 경로일 뿐, 전체 진단/시그널 응답 실패 자체를 고쳤다는 증거는 아니다. 배포 후 독립 카드의 실제 응답과 Railway 서버 로그를 확인해야 한다.
