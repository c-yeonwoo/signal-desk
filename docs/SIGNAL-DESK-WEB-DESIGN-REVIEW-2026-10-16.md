# Signal Desk 웹 디자인 개선안 — 읽는 순서를 다시 설계한다

작성: 2026-10-16. 코드 기준: `main@b206615`(#731). 운영 Chrome에서 `#today`, `#signal`, `#trading/rebal`, `#admin/ops`를 직접 열어 본 결과다. **설계 산출물이며 운영 UI 변경은 아니다.**

[기존 3.0 설계](SIGNAL-DESK-3.0-REBOOT-DESIGN-2026-10-05.md)의 실행 보완 문서다. 새 버전이나 새로운 완료율을 만들지 않는다. 메뉴의 역할, 입력 출처, 연구·매매 잠금은 그대로 두고 화면 구성·문구·시각 체계를 구체화한다. 수익성 개선을 디자인의 성과로 주장하지 않는다.

## 1. 결론

지금 화면은 기능이 없는 것이 아니라 **모든 기능이 자기 설명을 앞에 두고 있다.** 검증 안내, 공부, 급변 종목, 탐색, 기업 설명, 후보 근거가 각자의 카드와 문장을 갖는다. 그래서 중요한 가격·현재 보유·다음 확인이 늦게 나온다. 안내를 더 붙이는 방식으로는 해결되지 않는다.

방향은 **차분한 투자 작업대**다. 기존 인디고 브랜드와 시황 그림은 살리고, 카드의 수와 중복 설명은 줄인다. 각 화면은 첫 화면에서 질문 하나에 답하고 행동 하나를 제안한다.

| 화면 | 첫 화면이 답할 질문 | 우선 행동 | 먼저 보여주지 않을 것 |
|---|---|---|---|
| 오늘 | 확인한 시장은 어떻게 움직였나? | 관련 종목 보기 | 전체 지표 원문·연구 대기·산업 공부 |
| 종목 | 가격과 후보 판단, 최근 근거가 같은 방향인가? | 해당 종목의 근거 확인 | 전체 시장 최대 상승·연구 성과·산업 전체 지도 |
| 내 투자 | 어떤 보유를 먼저 확인해야 하나? | 현재 입력으로 보유 확인 | 오래된 진단 전문·목표 비중 입력 폼 |
| 관리자 | 무엇이 멈췄고 무엇을 해야 하나? | 문제별 확인/복구 동선 | 정상 로그·연구 검증 수치의 장문 나열 |

첫 화면을 짧게 만든다고 중요한 위험을 접지는 않는다. **가격 지연, 진단 입력 불일치, 주문 불가 이유는 해당 숫자·행동 바로 옆에 남긴다.** 원문·계산식·과거 기록만 뒤로 옮긴다.

## 2. 조사 범위와 실제 발견

### 관찰 방법과 한계

- 운영 로그인 상태에서 데스크톱 화면과 접근성 트리를 확인했다. 실제 계좌 금액·개인 식별정보는 문서와 시안에 복사하지 않았다.
- `index.html`, `home.js/css`, `investment.js/css` 및 기존 로드맵을 대조했다. `index.html`은 12,392줄이다. 길이만으로 성능 결함을 판정하지 않는다.
- 오늘 화면의 근거 영역은 관찰 당시 펼쳐져 있었다. 기본 설정이 펼침이라는 뜻은 아니다.
- 내 투자 화면은 비동기 로딩 후 실계좌 보유가 표시됐다. 초기 빈 상태를 계좌 미연결의 증거로 해석하지 않는다. 로딩 중과 실제 빈 상태를 구분할 필요가 있다.
- 모바일 실기기, 키보드 전 경로, 색각 시뮬레이션, Core Web Vitals는 이번에 측정하지 않았다. 아래 관련 사항은 구현 수용 조건이지 통과 결과가 아니다.

## 3. 유지·이동·제거의 경계

**유지:** 오늘·종목·내 투자 구조, 국내·해외·관심 탭, 결정적 시황 SVG, 회사별 원문/시각/누락, 분석용 입력과 실계좌 분리, 관리자 네 군집, 기존 딥링크.

**이동:** 산업 연결·공부는 종목 상세의 관련 근거 뒤로, 급변 연구는 탐색 내부의 연구 영역으로, 판별력·빈자리·놓친 상승 분석은 연구 화면으로, 목표 비중·배당 조정은 내 투자에서 필요할 때 여는 도구로 옮긴다. 별도 관심 메뉴나 인사이트 메뉴는 다시 만들지 않는다.

**화면에서 제거:** 같은 제목의 재출력, 읽지 않아도 되는 카드 접두사, 후보 설명의 반복, 장식용 배지, 현재 과업과 무관한 전역 장문 경고. 원문·이력·연구 데이터는 삭제하지 않는다.

**이번에 하지 않음:** 엔진 점수·정렬 공식 변경, 뉴스 감성 합산, 자동 주문 승인, 계좌 자동 합산, React/Tailwind 전환, 새 차트/애니메이션 라이브러리 도입, 일일 LLM 이미지 생성 호출, 브랜드명 교체. 디자인 때문에 운영 API를 반복 호출하지 않는다.

## 4. 화면별 확정 배치

### 4.1 오늘 — 진단과 그림을 함께, 반복은 없이

데스크톱 콘텐츠 최대 폭 1,200px. 상단은 7:5 두 칸, 모바일은 진단→장면 순서다.

```text
오늘                         국내 | 해외
미국 · 10월 15일 종가 · 확인한 502종목
오른 종목이 더 많았어요       [같은 상태를 표현하는 시황 장면]
380 / 502종목 상승            [숫자·제목을 다시 쓰지 않음]
최근 흐름은 종목마다 달라요
일부 종가 누락 · 후보 건수 보류
[종목 보기]  근거 보기
────────────────────────────────────────
관심종목에 생긴 변화  최대 3건 / 없으면 ‘새로 확인한 변화 없음’
경제 일정·원문은 근거 보기 안으로
```

- 시장 전체가 아니라 수집한 범위임을 기준 줄에 남긴다. 502/503과 종목 목록 504처럼 서로 다른 표본·시각의 수는 같은 수처럼 맞추지 않는다. 분모·기준일이 다르면 각각 명시한다.
- 핵심 문장 1개, 수치 근거 2개 이내. 결측이 있으면 영향을 받는 내용 옆에 이유를 쓴다. 긴 `아직 모르는 점` 전체를 헤드라인 밑에 붙이지 않는다.
- 장면은 데스크톱 높이 약 220–280px, 모바일 160px부터 조정. 내용이 커지면 고정 높이로 자르지 않는다. 장면의 햇빛·구름은 현재 자료 상태의 비유이지 미래 방향이 아니다.
- HTML 텍스트가 진단의 단일 접근성 원천이다. 중복 장식 SVG는 `aria-hidden`으로 두되, SVG에만 존재하는 의미가 생기면 텍스트로도 제공한다.
- 이미지 저장은 같은 스냅샷으로 생성한 내보내기 포스터를 사용한다. 페이지용 장면과 공유용 제목을 억지로 같은 레이아웃에 넣지 않는다. LLM 이미지 생성은 필요하지 않다.
- 관심이 비어 있으면 등록 동선을 작은 한 줄로 제공한다. 새 API가 필요하면 해당 부분만 후순위로 두고 시장 카드 구현을 막지 않는다.

### 4.2 종목 — 목록과 근거가 중심

데스크톱 1,440px 이상: 목록 360–420px, 상세 나머지. 1,024–1,439px: 목록 최소 300px. 1,024px 미만: 목록→별도 상세로 전환하고 뒤로 가면 검색·스크롤을 복원한다. 경계값은 초기 설계값이며 실제 긴 한글 종목명으로 조정한다.

상단에는 검증 상태 한 줄과 시장 탭·검색·정렬만 둔다. `상세 탐색`은 같은 줄의 보조 버튼이다. 목록에는 이름, 가격/등락, 후보 등급을 먼저 표시한다. 코드·업종은 두 번째 줄, 점수·자료 비중은 선택 상세로 옮긴다. 작은 화면에서 열을 늘리지 않고 가격 두 줄을 우측 정렬한다. 신선한 장중 가격이 없으면 **확정 종가**라고 적고 장중 가격처럼 보이게 하지 않는다.

상세의 순서:

1. 회사명·코드·관심 저장. 회사 소개는 접을 수 있는 한 줄.
2. 가격과 등락, 각각의 기준. 시세 갱신 시각과 후보 계산 기준일을 구분한다.
3. 기존 후보 등급 + `종가 기준 후보 평가` 설명. 주문 가능 여부는 별도 상태로 표시한다. `강력매수` 내부 등급을 숨겨 조작하지 않고 `매수 후보 · 등급: 강력매수`처럼 역할을 설명한다. 향후 명칭 변경은 별도 결정이다.
4. 긍정 근거 최대 2개 / 주의·미확인 최대 2개. 추가 원문은 `근거 전체 보기`에서 열 수 있다. 서로 다른 사실을 억지로 2개에 합치지 않는다.
5. 차트. 점수와 가격의 축·기준일을 명확히 분리. 최초 후보 표시 이후 변화는 **보유 수익률이 아님**을 바로 옆에 표시한다.
6. 사용자 보유가 확인되면 `내 보유 확인` 연결. 회사 관련 이슈·산업 연결·용어 설명은 그 아래.

후보 배지는 버튼처럼 보이지 않게 테두리/높이/커서/포커스를 구분한다. `관심 저장`은 실제 버튼으로 44px 터치 영역을 갖는다. 오른쪽 큰 등급 박스 때문에 가격 아래가 빈 행이 되지 않도록 가격·상태는 독립 grid area로 배치한다.

**상태 일치 계약:** 상세 응답은 `(시장, 종목 ID, 요청 버전)`이 현재 선택과 일치할 때만 반영한다. 시장/검색을 사용자가 바꿔 선택 항목이 제외되면 선택 해제. 가격 자동 갱신·자동 재정렬만으로 읽던 상세를 빼앗지 않는다. 갱신 중 목록 순서는 유지하고 `새 순서 적용`으로 명시적 갱신하는 방식을 우선한다.

### 4.3 내 투자 — 계좌를 합치는 대신 현재 보는 대상을 명확하게

```text
내 투자          국내 | 해외
보유 출처: 실계좌 조회 / 분석용 입력    마지막 조회 시각
[현재 출처의 보유 요약 · 통화별 표시]
분석용 입력이 실계좌와 달라요  [차이 확인]
먼저 확인할 보유              [근거 있는 문제만]
보유 목록                    [종목 상세로]
계좌·주문 기록 / 비중 미리보기 / 배당 / 지난 진단
```

- 실계좌 조회값과 분석용 입력은 출처 선택으로 구분한다. 진단이 여전히 분석용 입력만 지원하면 `분석용 입력 기준`을 진단 제목에 고정한다. 출처를 선택했다고 진단 대상을 자동 변경하지 않는다.
- 계좌에서 분석용으로 복사하기 전 **추가·수량 변경·제외될 종목의 차이**를 보여주고 확인받는다. 국내 입력 전체 교체를 조용히 실행하지 않는다. 이미 존재하는 서버 계약을 확인한 뒤 연결한다.
- 과거 진단의 입력 확인 불가는 `지난 진단은 현재 보유와 비교할 수 없어요` 한 줄로 바꾸고 기록에 보관한다. 현재 보유 입력이 없으면 진단 버튼 대신 입력 경로가 우선이다.
- 조회 중은 `계좌 확인 중`, 조회 실패는 `계좌를 확인하지 못했어요`, 실제 0종목은 `조회한 계좌에 보유종목이 없어요`. 세 상태를 같은 빈 화면으로 처리하지 않는다.
- 큰 도넛 차트보다 종목별 금액·비중 목록을 먼저 제공한다. 집중도 비교가 필요한 경우 수평 막대와 정확한 숫자를 병기한다. 작은 조각의 긴 외부 라벨을 늘리지 않는다.
- 확인된 입출금·비용이 없으면 전체 투자 수익률 그래프를 만들어내지 않는다. 평가금액과 수익률을 분리하고 통화 간 합산은 이 작업 범위 밖이다.
- 주문은 조회/조건 확인/승인 경계를 보존한다. 접힌 주문 영역을 열었다고 주문 가능 상태가 되지 않는다. 배당은 확정과 예상, 지급일과 기준일을 분리한다.

### 4.4 관리자 — 문제 카드만 먼저

현재 `서비스 상태 / 데이터 / 연결·비용 / 연구` 구조를 유지한다. 일반 상단에서 관리자를 프로필 안으로 이동하되 관리자 직접 URL·권한 검사는 유지한다.

문제 카드 표준은 `문제 + 영향 + 마지막 확인 + 다음 조치`다. 자동 재시도 중이면 그 상태를 적고 의미 없는 수동 버튼을 만들지 않는다. `연구 표본 대기`는 서비스 장애 색상을 쓰지 않는다. 고급 설정을 다시 삭제하거나 연구 이력을 덮지 않는다.

## 5. 시각 체계 — Quiet Desk

[색상·컴포넌트 참고 HTML](prototypes/signal-desk-quiet-desk.html)은 디자인 시안이다. 예시 수치는 합성 데이터이며 운영 API·계좌·주문과 연결되지 않는다.

시안 검수: 인라인 JavaScript 구문, 11색/4그룹 생성, 9개 대비 예제 중 권장 8조합의 4.5:1 충족, 문서 링크와 외부 의존성 없음을 정적 실행으로 확인했다. 기존 회색 비교 예제 1개는 의도적으로 미달로 표시한다. 브라우저의 로컬 파일 URL 정책으로 시안 렌더링은 확인하지 못했으므로 픽셀·모바일 검수 완료로 세지 않는다. 앞 절의 운영 화면 관찰과 이 시안의 검수 상태는 별개다.

### 팔레트

기존 브랜드 `#243CDB`를 유지한다. 중립 표면을 대부분으로 사용하고 인디고는 선택/행동, 녹색·적색은 수치 변화, 황토색은 확인이 필요한 상태에 제한한다. 화면을 녹색으로 물들여 매수 확신을 만들지 않는다.

| 그룹 | 토큰 | HEX | 용도 |
|---|---|---|---|
| Primary | ink | #151A22 | 제목·본문 |
| Primary | brand | #243CDB | 주요 행동·선택·포커스 |
| Primary | brand-soft | #ECEEFE | 선택 영역 배경 |
| Secondary | text-secondary | #526071 | 설명 |
| Secondary | positive | #0B7655 | 양의 수치 변화 |
| Secondary | line | #CBD2DC | 장식 구분선, 입력 경계의 유일한 표시로 사용 금지 |
| Neutral | canvas | #F6F7F9 | 페이지 바탕 |
| Neutral | surface | #FDFDFC | 콘텐츠 표면 |
| Neutral | text-muted | #637083 | 기준시각·보조 메타 |
| Accent | negative | #B73333 | 음의 변화·오류 |
| Accent | caution | #8A5700 | 확인 필요 |

표면 `#FDFDFC` 대비 텍스트 대비: 보조 6.31:1, 메타 4.94:1, 브랜드 7.52:1, 양의 변화 5.52:1, 음의 변화 5.84:1, 주의 5.99:1. 선형 sRGB 상대 휘도로 계산했다. 조합별 원값으로 판정하며 반올림된 수를 통과 기준으로 쓰지 않는다. 반투명·disabled·선택 배경은 구현 시 각각 다시 확인한다.

현재의 상승 녹색/하락 적색 체계를 이번에 반대로 바꾸지 않는다. `▲ +2.4% / ▼ −1.8%`처럼 기호·부호를 함께 쓴다. 국내/해외 색상 관례를 자동으로 뒤집거나 사용자가 익힌 색의 의미를 바꾸지 않는다. 가격 상승과 추천 강도를 같은 녹색 농도로 표현하지 않는다.

### 글자·간격·표면

- 본문 16px/1.6, 보조 14px/1.5, 시각·코드 13px/1.45. 핵심 금액 32px, 화면 제목 28px, 섹션 20px. rem 기반으로 확대 가능하게 한다. 핵심 위험은 메타 크기로 축소하지 않는다.
- 금액·비율은 tabular-nums, 천 단위 구분, 일관된 통화 형식. 종목명은 잘려도 전체 이름을 키보드/터치로 확인할 경로를 둔다.
- 4/8/12/16/24/32/48px 간격 척도. 카드 내부 24px, 모바일 16px. 설명의 최대 줄 폭은 약 60–68자; 브라우저 폭 전체에 문장을 펴지 않는다.
- 큰 표면 반경 16px, 작은 입력 8px. 모든 행을 카드로 감싸지 않는다. 기본 카드 그림자는 없고 떠 있는 메뉴에만 사용한다.
- 주요 컨트롤 높이 44px, 입력 글자 16px. 이는 프로젝트 사용성 기준이며 WCAG AA의 최소 포인터 크기 24px와 동일한 요구라고 설명하지 않는다.
- `:focus-visible` 인디고 외곽선과 간격, 선택 탭의 텍스트/밑줄/ARIA 상태, 오류의 문장과 아이콘을 함께 제공한다.

### 모션

Emil 스킬의 핵심을 **자주 쓰는 동작일수록 움직임을 줄이는 것**으로 적용한다. 시세·정렬·차트에 장식 애니메이션을 넣지 않는다. 메뉴와 접힘은 필요할 때만 120–180ms의 opacity/transform으로 피드백하며 `prefers-reduced-motion`에서는 제거한다. `transition: all`, 무한 반짝임, 숫자 카운팅, 매 행 stagger는 쓰지 않는다. hover 효과는 hover 가능한 기기에만 적용한다.

## 6. 문구와 상태를 공통 계약으로

문장 생성 LLM을 추가하지 않는다. `ui-copy.js`의 상태별 템플릿과 `ui-format.js`의 `Intl.NumberFormat/DateTimeFormat`으로 통일한다. 서버 사실값은 그대로 받고, UI가 원인·확률·주문 결론을 새로 추론하지 않는다. 자연어가 다른 데이터 객체를 하나로 뭉개지 않도록 종가일/시세시각/공개시각/확인시각을 각각 입력받는다.

| 현재 표현 또는 사용 패턴 | 제안 표현 | 보존할 의미 |
|---|---|---|
| 점수 자료 100% | 점수 계산에 필요한 자료 100% 확보 — 상세에서만 | 성공 확률·뉴스 검증률이 아님 |
| 강력매수 단독 대형 배지 | 매수 후보 · 등급: 강력매수 | 기존 엔진 등급 유지, 개인 매수 지시 아님 |
| 발동 후 −26.1% | 첫 후보 표시 이후 가격 −26.1% · 보유 수익률 아님 | 최초 표시일·기준가격·비용 미포함 유지 |
| 최근 n개 종가 평균 위 | 최근 평균보다 높은 종목 — 상세에 n거래일과 공식 | 지표 뜻과 실제 기간을 숨기지 않음 |
| 관찰 종목의 흐름이 엇갈려요 | 확인한 종목은 상승이 더 많지만, 최근 추세는 뚜렷하지 않아요 | 자료가 뒷받침할 때만 조합. 항상 출력하는 문구 아님 |
| 근거 없음 | 최근 회사 관련 원문을 확인하지 못했어요 | 호재·악재가 없다는 주장 아님 |
| 진단 당시 입력을 확인할 수 없어요 | 지난 진단을 현재 보유와 비교할 수 없어요 | 과거 결과를 현재 행동으로 재사용하지 않음 |
| 내 투자 데스크 / 오늘의 투자 상태 / 내 행동 | 내 투자 / 먼저 확인할 보유 | 같은 화면의 중복 제목 제거 |

톤은 짧은 설명체로 통일한다. 제목은 결론, 본문은 이유, 마지막은 가능한 행동이다. “인사이트를 제공해요”, “종합적으로 고려해보세요” 같은 내용 없는 끝맺음을 제거한다. 다만 불확실한 것을 “상승합니다”로 바꾸지 않는다.

| 데이터 상태 | 보이는 내용 | 동작 |
|---|---|---|
| 첫 로딩 | 영역의 고정된 자리와 구체적 로딩 문장 | 0원·0종목·보유 없음 표시 금지 |
| 정상 | 값 + 해당 기준시각 | 업데이트로 페이지 전체를 초기화하지 않음 |
| 일부 누락 | 유효한 값 + 누락 영향 | 누락에 의존하는 결론만 보류 |
| 오래된 값 | 마지막 확인값 + `갱신 지연` | 보존값을 현재 실시간처럼 표시하지 않음 |
| 휴장/장 종료 | 마지막 정상 거래일 기준 | 휴장 자체를 장애로 칠하지 않음 |
| 조회 실패 | 기존 자료 유지 여부와 실패 이유 | 읽기 요청 재시도만, 주문 자동 재실행 금지 |
| 실제 빈 결과 | 현재 필터/출처에 결과 없음 | 필터 초기화나 입력 연결, 가짜 추천 금지 |

상태 토스트는 중요한 변경에만 사용한다. 매 가격 갱신마다 화면 낭독이나 알림을 반복하지 않는다. 주문·자료 실패는 일시 토스트만으로 사라지지 않고 해당 영역에도 남긴다.

## 7. 구현 구조와 로딩

전체 재작성 대신 화면 단위로 옮긴다. `index.html`에 CSS를 계속 덧붙이지 않는다.

| 책임 | 제안 경계 | 주의점 |
|---|---|---|
| 색·간격·글자 | `web/design-tokens.css` | 기존 변수 alias를 둔 뒤 해당 화면부터 이전 |
| 버튼·상태·시각·근거 묶음 | `web/ui-components.css` 및 작은 렌더 함수 | 아직 다른 화면에 이전하지 않은 CSS를 전역으로 덮지 않음 |
| 문구·숫자·날짜 | `web/ui-copy.js`, `web/ui-format.js` | 렌더링 시 textContent/기존 escaping, 뉴스 HTML 직접 삽입 금지 |
| 오늘 | 기존 `home.js/css` | 같은 스냅샷으로 HTML과 그림 생성 |
| 종목 | 목록·상세 함수부터 별도 모듈 | 기존 URL·선택·요청 취소 계약 유지 |
| 내 투자 | 기존 `investment.js/css` | 원천 출처와 조회/입력/주문 권한을 섞지 않음 |

현재 head의 ECharts 동기 외부 로드는 차트 없는 첫 화면도 기다리게 할 수 있는 코드상 후보다. **실측 원인이라고 확정하지 않는다.** 첫 구현에서 네트워크/성능 기준값을 측정하고, 차트 초기화 의존 순서를 확인한 뒤 lazy loader를 적용한다. 종목 텍스트와 위험은 차트보다 먼저 나온다. 숨긴 원문·진단 기록 요청은 실제로 지연해야 한다. 단순히 CSS로 숨기는 것은 성능 개선이 아니다.

가격 캐시를 길게 늘려 빠르게 보이게 하지 않는다. 기존 조회 주기·시세 TTL·장중 가드는 유지한다. 늦게 온 응답은 현재 종목에 덮지 않고, 캐시된 값은 기준시각과 함께 표시한다. 저장·주문·계좌 복사는 낙관적 성공 UI로 확정하지 않는다.

### 필요한 검증만

1. 화면별 정상·로딩·빈값·지연·실패·입력 불일치 fixture. 상태 매핑과 늦은 응답 덮어쓰기에는 좁은 자동 테스트를 둔다.
2. 1,440px, 1,024px, 390px 및 320 CSS px에서 주요 과업 확인. 200% 글자 확대와 키보드 접근 확인. 실제 휴대전화 터치 평가는 별도로 기록한다.
3. 일반 텍스트 4.5:1, 의미 있는 경계·포커스의 대비, 색상 없이 상태 구분. 자동 검사만으로 접근성 완료라고 하지 않는다.
4. 같은 환경·캐시 조건에서 첫 방문/재방문 각 3회 전후 비교. 중앙값과 편차, 첫 본문 표시, 종목 선택 응답, 레이아웃 이동을 기록한다. 운영의 p75 Core Web Vitals를 이 표본으로 주장하지 않는다.
5. 원문 링크·기준시각·기존 딥링크·관심 저장·진단 입력·주문 확인 동선 회귀. UI 변경에 엔진 전수 재생을 반복하지 않는다.

위 절차는 며칠 장 관측 없이 시작할 수 있다. 다만 장중 실제 데이터 의미의 완료 증거는 기존 로드맵 조건을 대체하지 않는다.

각 묶음은 작게 PR·CI·순차 머지하고, 배포 확인 후 다음으로 진행한다. 데이터/엔진 파일이 예상 밖으로 바뀌면 분리한다. 첫 PR은 D1이다. 색상 전체 교체와 계좌 구조 변경을 한 PR에 넣지 않는다. 사용자가 실제 동선에 반대하거나 새 판단 의미가 필요할 때만 설계로 돌아온다.

진행률은 `문서 작성`, `구현`, `운영 확인`, `기존 관문 완료`를 분리한다. 이 설계 작성으로 **통합 40/100, 3.0 30/100은 그대로**다. D1~D6를 마쳐도 엔진 수익성이나 데이터 관문 점수를 자동 지급하지 않는다.

### D6 실측 기록 — 2026-10-16

운영 `?v=d5-f7c1b54#today`, Chrome DevTools, 390×844 CSS px, 모바일 터치, Fast 4G, CPU 1× 조건이다. 캐시를 비운 첫 탐색 1회와 일반 재탐색 2회를 연속 측정했다. CrUX 실사용자 자료는 없다.

| 탐색 | LCP | CLS |
|---|---:|---:|
| 캐시 비움 | 3,328 ms | 0.31 |
| 재탐색 1 | 4,387 ms | 0.29 |
| 재탐색 2 | 984 ms | 0.31 |
| 중앙값 | 3,328 ms | 0.31 |

LCP는 API 응답 뒤 Blob URL로 생성하는 시장 그림에서 발생했고, 첫 두 탐색의 LCP 지연이 각각 3.1초·4.2초였다. CLS는 0.29~0.31로 나빴다. 이동 원인은 Pretendard 웹폰트가 약 3.2초 뒤 도착해 글자 폭을 바꾸는 것과, 늦게 표시되는 시황 영역이었다. Lighthouse 모바일 접근성은 100점이었다. 390px 에뮬레이션에서 가로 넘침은 없었다. 별도 render-blocking 분석은 첫 탐색 FCP가 최대 207ms 줄 여지를 제시했다.

D6 첫 수정은 ECharts·화면 JS를 `defer`로 옮겨 HTML 파싱과 병렬 로드하고, 로그인 성공 뒤 DOM 준비를 확인하고 앱을 시작하도록 했다. Pretendard CDN 연결·기본 세 굵기를 선요청하고, 이미지와 같은 크기의 자리표시자를 먼저 두어 그림 도착 시 재배치를 막는다. API·시세 캐시, 요청 주기, 판정·주문 로직은 바꾸지 않았다. 배포 뒤 같은 조건 3회와 화면 폭 회귀를 다시 기록한 뒤 D6 완료 여부를 판정한다.
