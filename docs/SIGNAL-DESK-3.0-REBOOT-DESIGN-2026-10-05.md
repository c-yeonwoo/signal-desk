# Signal Desk 3.0 리부팅 설계와 로드맵

작성일: 2026-10-05. 조사 기준: `main@ece614d`. 상태: 3.0 설계 기준 문서; 구현 현황은 마지막 절에 기록.

Signal Desk 3.0은 시장의 변화와 기업의 근거를 함께 읽고, 내 보유 상황에 맞게 다음 확인을 돕는 서비스로 재구성한다. 사용자가 정량 점수와 뉴스와 계좌를 직접 조립해야 하는 현재 경험을 개선하는 것이 우선이다. 기능 수나 화면 수를 늘리는 것은 목표가 아니다.

사용자가 전달한 초보자 5명의 10개 피드백을 정성적 발견으로 채택한다. 참여자별 답변·동일 과업 결과는 제공되지 않았으므로 특정 과업의 성공률을 산출하지 않는다. 기존 UI/UX 5/6(83%)는 구현 목록의 이행률이며 제품의 이해도나 만족도 점수가 아니다. 기존 6단계 검증은 미완료로 보존하고, 이번 설계의 재검증에 연결한다. 데이터 확장 장부의 60%와 엔진 사전등록 검증은 별도다.

## 1 확인한 문제와 설계 결정

| 피드백 | 현재 구조에서 확인한 점 | 3.0 결정 |
|---|---|---|
| 1 그림으로 시황을 이해하고 싶다 | `market_brief_image.py`는 지표와 문자를 배치한 결정적 SVG다. 그림 생성 모델이 장면을 만드는 경로가 아니다. | 업종과 시장 구조를 장면으로 보여주는 시황 일러스트레이션 도입 |
| 2 흐름 진단이 모호하다 | `market_brief.py`는 60개 종가 평균 상회 비율 40~60% 구간을 같은 문장으로 묶는다. | 당일 방향·상승 범위·주도 업종·지속성을 따로 계산한 뒤 하나의 구체적 진단으로 설명 |
| 3 내 투자데스크의 용도를 모르겠다 | 진단·도구·장부가 중심이고 방문 시 확인할 일이 드러나지 않는다. | 첫 화면을 내 자산 변화와 먼저 확인할 종목 중심으로 재편 |
| 4 내 투자와 실계좌가 왜 나뉘는가 | 동일한 사람의 보유정보와 주문 동선이 병렬 탭이다. | 내 투자 한 화면에 계좌 상태·보유·주문 이력을 연결 |
| 5 진단과 비중 도구가 어렵다 | 기능 이름을 먼저 읽고 사용자가 목적을 추론해야 한다. | 보유 종목 확인과 비중 변경 미리보기로 바꾸고 필요한 입력만 질문 |
| 6 배당 계획의 효용을 모르겠다 | 독립 탭이 계획 도구를 먼저 노출한다. | 내 투자의 선택 항목으로 이동, 확정 입금과 추정 배당부터 표시 |
| 7 시그널과 이슈가 나뉘어 있다 | 인사이트에 산업·이슈·공부가 따로 있다. | 종목별 판단 화면에 가격·기업 변화·뉴스·개인 보유를 결합 |
| 8 둘을 함께 판단해 주길 원한다 | 감성 점수는 engine 합산에서 제외되고, 공식 위험과 참고 설명은 다른 경로다. | 근거의 일치·충돌·누락을 설명하는 공통 판단 화면과 데이터 계약 설계 |
| 9 관리자가 복잡하다 | 운영·뉴스·발행·엔진·검증 분류는 있으나 하나의 문제가 여러 카드에 중복될 수 있다. | 장애 한 건을 중심으로 영향·원인·복구를 묶고 데이터·연결·연구로 분류 |
| 10 전면 재정비가 필요하다 | `index.html` 11,150줄, `api.py` 6,582줄에 화면·상태·문구가 넓게 분산돼 있다. 줄 수 자체가 오류의 증거는 아니지만 변경 결합도가 높다. | 기능 목록 중심에서 사용자 과업 중심으로 전환하고 화면별 점진 분리 |

이번 조사는 저장소의 구현과 기존 운영 확인 기록을 기준으로 했다. 피드백 이후 운영 서버를 새로 재점검하거나 사용자 행동을 계측한 결과는 아니다.

## 2 서비스의 약속과 브랜드

브랜드명은 우선 Signal Desk를 유지한다. 서비스 소개는 “시장 흐름부터 내 종목까지, 판단에 필요한 근거를 한곳에”로 제안한다. 새 이름·로고·도메인은 핵심 과업의 이해도를 확인한 뒤 결정한다.

사용자가 얻어야 하는 결과는 세 가지다. 오늘 어떤 변화가 있었는지 설명할 수 있고, 관심 종목의 긍정적 근거와 우려를 함께 찾을 수 있으며, 내 보유에서 다음으로 확인할 항목을 알 수 있어야 한다. 알림 클릭이나 접속 횟수만으로 성공을 판단하지 않는다.

화면 말투는 친절한 설명체로 통일한다. “상승 모멘텀 둔화”는 “최근 상승 속도가 줄었어요”처럼 풀고, 기간·대상·비교 기준은 보존한다. 종목 코드·통계 용어·운영 용어는 상세에서 확인하도록 한다. 모든 제목은 화면이 답하는 사용자 질문과 연결한다.

## 3 메뉴와 화면의 역할

주 메뉴는 `오늘 | 종목 | 내 투자` 세 개다. 관리자와 환경설정은 프로필 메뉴에 둔다.

| 새 화면 | 첫 화면에서 답할 질문 | 흡수하는 기존 기능 |
|---|---|---|
| 오늘 | 오늘 시장에서 무엇이 달라졌고 나와 관련된 변화는 무엇인가 | 시장 요약·시황 그림·관련 이슈·경제 일정 |
| 종목 | 이 기업을 지금 어떻게 볼까 | 시그널 목록과 상세·산업·최근 이슈·관심종목 |
| 내 투자 | 내 돈은 어떻게 변했고 어느 보유를 먼저 살펴볼까 | 내 투자·실계좌·주문 이력·비중 도구·배당 |

종목 목록은 사용자 선호대로 `국내 | 해외 | 관심`을 유지한다. 별도 관심종목 상단 메뉴는 만들지 않는다. 같은 종목은 어디에서 열어도 동일한 상세 화면과 기준시각을 갖는다.

인사이트 상위 메뉴는 제거하고 내용을 필요한 위치에 배치한다. 시장 이슈는 오늘 화면, 기업 이슈와 산업 관계는 종목 상세, 용어 설명은 해당 문구 옆에 둔다. 전체 학습 자료는 선택형 자료실로 유지한다. 봇 모의투자는 내 투자의 “모의투자 보기” 안에 두고 가상 장부임을 계속 표시한다.

모바일에서도 같은 정보 순서를 유지한다. 화면마다 핵심 행동은 한 개를 우선하고 보조 행동은 펼친 뒤 제공한다. 기존 URL은 새 화면의 대응 위치로 연결하고 기존 저장 메모·관심종목·장부는 보존한다.

현재 `index.html`의 hash 경로를 바탕으로 다음 연결을 유지한다. 실제 전환 때는 화면뿐 아니라 선택된 시장·계좌 하위영역도 복원한다.

| 현재 경로 | 3.0 위치 |
|---|---|
| `#signal` | 종목 · 국내 목록 |
| `#watchlist` | 종목 · 관심 목록 |
| `#trading`, `#trading/rebal` | 내 투자 · 개요 |
| `#trading/live` | 내 투자 · 계좌와 주문 |
| `#trading/dividend` | 내 투자 · 배당 확인 |
| `#trading/bot` | 내 투자 · 봇 모의투자 |
| `#cycle/cycle` | 오늘 · 시장 흐름 상세 |
| `#cycle/hypo` | 오늘 · 관련 이슈 |
| `#cycle/vc` | 종목 · 산업 연결 |
| `#cycle/learn`, `#cycle/guru`, `#cycle/etf` | 종목 · 용어와 학습 자료 |
| `#admin/*` | 권한이 있는 사용자만 프로필의 관리자 공간 |
| `#mypage` | 프로필과 계정 설정 |

화면 문구는 대상·비교 기간·판단 근거·확인하지 못한 점을 지킨다. “흐름이 엇갈려요”처럼 대상과 이유를 감춘 표현은 제목으로 쓰지 않는다. 기간이 다른 자료는 한 문장에서 비교하지 않는다. 확인되지 않은 자료는 “없음”으로 바꾸지 않고 확인 시각과 자료 부족 이유를 보여준다. 색만으로 매수·매도 상태를 전달하지 않는다.

## 4 오늘 시장 진단

현재의 단일 비율은 최근 평균 위에 있는 종목의 비중을 설명할 수 있다. 그것만으로 오늘 장이 횡보하거나 업종 순환이 일어났다고 단정할 수는 없다. 3.0은 다음 관측을 구분해 사용한다.

| 관측 | 필요한 자료 | 표현 범위 |
|---|---|---|
| 오늘 방향 | 동일 시장 세션의 지수·가격 | 지수와 관찰 종목이 오늘 올랐는지 |
| 상승의 범위 | 동일 세션 상승·하락 수, 기존 추세 지표 | 상승이 넓게 퍼졌는지 일부에 몰렸는지 |
| 주도 업종 | 업종별 관측 수와 동일 기간 수익률 | 어느 업종이 상대적으로 강했는지 |
| 지속성 | 사전에 정한 기간의 과거 관측·당시 구성 | 같은 현상이 며칠 이어졌는지 |
| 새로운 사건 | 발행시각·회사 귀속이 확인된 공시·기사 | 같은 시기에 확인된 사건과 가능한 연결 |

세션과 가격 종류가 다른 관측을 하나의 현재 상태로 섞지 않는다. 국내와 미국을 각각 진단한다. 장중 자료와 전일 종가 분석에는 서로 다른 기준시각을 붙인다. 추적 종목의 결과를 거래소 전체로 부르지 않는다. 지수 기여 자료가 없으면 업종 수익률만으로 “반도체가 지수를 끌어올렸다”고 쓰지 않는다.

사용자 문장은 상태·근거·다음 확인 순서다. 예를 들어 “지수는 올랐지만, 관찰 종목에서는 반도체가 강하고 소비재는 약했어요. 상승이 다른 업종으로 넓어지는지 확인할 때예요.”는 해당 관측이 있을 때만 표시할 설계 예시다. 현재 시장 진단이 아니다.

혼재 상태도 명확하게 설명할 수 있다. “지수는 제자리이고 업종별 등락이 갈렸어요”처럼 무엇이 섞였는지를 말한다. 자료 부족은 “미국 종가 갱신을 기다리고 있어요. 마지막 확인은 …”로 설명한다. 불확실성을 강세·약세로 억지 변환하지 않는다.

새 분류의 기간·커버리지·상태 경계는 구현 전에 문서화하고 고정된 대표 사례로 검증한다. 기존 매매 엔진의 국면·가중치·진입 조건은 그대로 두며, 제품 설명용 분류가 주문 입력으로 흘러가지 않게 한다.

## 5 시황을 보여주는 그림과 애니메이션

첫 시안은 업종을 서로 다른 건물로 표현하는 “시장 풍경”을 제안한다. 반도체·자동차·소비재 등 실제 관측 업종이 하나의 장면에 배치되고, 강한 업종과 약한 업종의 대비가 드러난다. 광범위한 상승은 장면 전반의 변화로, 일부 업종 강세는 해당 건물만 강조해 표현한다. 낮은 커버리지는 그 구역을 비워 명시한다.

그림에 붙는 한 문장은 반드시 관측된 시장 진단을 요약한다. 화살표·속도·크기를 미래 상승률이나 실제 자금 이동으로 오해하게 만들지 않는다. 수급 자료가 없는 상황에서 돈이 이동하는 애니메이션을 쓰지 않는다. 첫 화면은 정지 장면만으로 이해되고, 짧은 모션은 상태가 바뀌었을 때만 사용한다. 모션 줄이기 설정과 텍스트 대체 설명을 제공한다.

제작은 두 부분으로 구성한다. 이미지 생성 모델은 일관된 스타일의 업종·배경·오브젝트 자산을 만들고, 코드가 검증된 관측에 맞춰 선택·배치·강조한다. 날짜·수치·회사명은 HTML/SVG로 합성해 오자를 방지한다. 화면의 그림도 동일한 market snapshot ID를 사용한다. 데이터가 바뀌면 이전 장면을 현재 설명으로 재활용하지 않는다.

매일 새로 그린 편집 일러스트는 2차 옵션이다. 검증된 장면 명세만 모델에 전달하고, 생성이 늦거나 실패하면 동일 진단을 표현하는 기본 장면을 즉시 제공한다. 그림 완성을 기다리느라 본문 로딩을 막지 않는다. 생성 결과가 검수되지 않은 동안 사실 근거로 사용하지 않는다.

모델 선택은 같은 장면 명세로 인물·회사명 없는 자산 제작 품질, 일관성, 지연, 이미지당 비용을 대조한 뒤 고정한다. 이번 설계에서는 특정 상용 모델이 더 우수하다고 가정하거나 새 API 키를 요구하지 않는다. 키는 서버의 제공자별 비밀변수로만 보관한다. 실사용 호출 예산과 보존 기간은 운영 설정으로 제한한다.

## 6 정량과 정성을 함께 읽는 종목 화면

종목 화면의 첫 질문은 “지금 이 종목에서 무엇을 보고 있는가”다. 구조화된 응답은 현재 조건, 긍정 근거, 반대 근거, 다음 확인, 내 보유와의 관계로 구성한다. 원문을 열면 해당 주장에 쓰인 문장·발행시각·수집시각·회사 식별을 함께 확인한다.

| 항목 | 종목 화면의 역할 |
|---|---|
| 현재 매수 조건 | 기존 엔진 결과와 그 결과의 이유를 설명 |
| 기업의 새 변화 | 검증된 공시·재무 변화, 귀속이 확인된 최신 뉴스 제공 |
| 함께 보면 | 가격 조건과 기업 근거가 일치하는지, 충돌하는지, 연결 근거가 없는지 설명 |
| 내 보유와의 관계 | 보유 여부·비중·추가 시 집중 변화 설명 |
| 다음 확인 | 판단을 재검토할 자료·예정된 발표·가격 갱신 조건 제시 |

예시: 가격 조건은 후보권이어도 사업 개선의 최신 근거가 없으면 “가격 조건은 후보에 들어왔어요. 최근 사업 상황은 추가 확인이 필요해요”라고 설명한다. 사업 개선이 있어도 가격 조건 미충족이면 두 상태를 그대로 보여준다. 정량·정성의 동의 개수를 상승 확률이나 새 매수 점수로 변환하지 않는다.

긍정 근거와 우려는 각각 최대 두 개를 먼저 보여준다. 남은 근거와 상세 수치는 접는다. 일반 뉴스는 설명과 다음 확인에, 검증된 공식 위험은 기존에 승인된 위험 경로에 연결한다. 산업상 인접하다는 이유만으로 특정 회사의 수혜를 확정하지 않는다. 같은 원문을 재인용한 기사들은 하나의 사건으로 묶는다.

현재 STRONG_BUY 등급은 사용자 첫 화면에서 “현재 매수 후보”라는 의미와 함께 표시하고, 기존 강도 등급·순위·산출 근거는 상세에 남기는 방안을 시안으로 검증한다. 레이블 개선을 순위나 규칙 교체로 사용하지 않는다. 연구 검증 상태는 짧고 일관된 위치에 유지한다.

LLM은 승인된 근거 묶음의 문장을 정리한다. 핵심 상태와 허용된 결론은 코드가 정한다. 출력은 claim별 evidence ID, 주장 종류, 시점, 한계를 포함하고 원문에 없는 숫자·회사 관계·목표가격은 거부한다. 공급자 실패 시 검증된 사실 템플릿으로 돌아간다.

향후 정성 정보로 후보 순위나 매매 조건까지 바꾸려면 별도 사전등록·전진 관측·비용 후 검증을 수행한다. 이번 3.0 출시의 완료 조건은 그 연구의 성공과 분리한다.

## 7 내 투자 화면

내 투자 첫 화면은 평가금액·기간 손익·마지막 계좌 동기화 시각을 보여주고, “먼저 확인할 보유”를 최대 세 개로 제시한다. 각 항목은 무엇이 달라졌는지, 내 보유에 왜 관련되는지, 다음 화면에서 무엇을 할 수 있는지 설명한다. 문제가 없으면 “새로 확인할 변화가 없어요”로 끝낸다.

계좌 연결이 있으면 증권사 계좌가 기준이다. 연결이 없으면 “직접 입력한 보유”로 표시한다. 두 입력이 같은 계좌라고 자동 추정해 합산하지 않는다. 연결 전·연결 중·정상·동기화 지연·인증 만료 상태를 각각 설계한다. 마지막으로 받은 잔고에는 기준시각을 남긴다.

실계좌·주문은 같은 내 투자 안에서 연다. 사용자가 보유 종목을 누르면 통합 종목 화면으로, 거래 이력을 누르면 해당 계좌의 주문·체결 내역으로 연결된다. 봇을 따르는 비중·한도는 계좌 설정에 둔다. 읽기 화면을 통합해도 주문 API의 권한·한도·멱등성·체결 상태 관리 책임은 유지한다.

| 현재 기능 | 새 진입 문구 | 사용자에게 보여줄 결과 |
|---|---|---|
| 보유진단 | 내 보유에서 확인할 점 | 집중·손실 기여·오래된 자료·새 사건 중 중요한 항목 |
| 진단기록과 검증결과 | 지난 확인과 달라진 점 | 당시 판단, 사용한 자료, 바뀐 사실 |
| 업종 비중 조정 | 이 종목을 더 사면 얼마나 몰릴까 | 지정 금액 전후의 해당 종목·업종 비중과 현금 |
| 목표 배당 | 앞으로 받을 배당 확인 | 지급 확정 내역과 추정 내역, 일정 미확인 |

비중 미리보기는 금액을 입력하거나 조절하면 결과가 즉시 바뀌는 방식이다. 입력하지 않은 금액을 임의 추천하지 않는다. 현재 보유·현금·가격이 충분할 때만 계산한다. 금액 입력→효과 확인→원할 때 주문 검토로 이어지고 주문은 별도 명시적 동작이다.

배당은 내 투자의 접힌 항목으로 옮긴다. “얼마를 언제 받는가”에 먼저 답하고 확정·추정·일정 미상을 구분한다. 목표 배당 역산은 사용자가 목표를 입력할 때만 제공한다. 기본 기능은 통화별로 표시하며 이번 리부팅에서 복수 계좌 합산·환율·세금 범위를 확대하지 않는다.

계좌 수익률은 입출금이 있으면 단순 평가액 증가율로 표시하지 않는다. 체결·입출금 자료가 부족하면 계산할 수 있는 손익만 보여준다. 모의투자와 실제 계좌 수익을 합치지 않는다.

## 8 관리자 화면

관리자 첫 화면은 지금 해결할 문제를 보여준다. 문제마다 영향 범위·발생 시각·마지막 성공·자동 재시도 상태·다음 조치 한 개를 붙인다. 예를 들어 시세 수집 장애가 여러 화면에 영향을 줘도 원인 장애는 한 건으로 묶고 영향을 받는 기능을 나열한다.

관리 메뉴는 `서비스 상태 | 데이터 | 연결·비용 | 연구` 네 그룹으로 제안한다. 서비스 상태는 장애와 복구, 데이터는 가격·공시·뉴스·보존, 연결·비용은 제공자 인증·쿼터·사용량, 연구는 잠긴 판정·실험 기록이다. 계좌의 개인 주문 비중은 내 투자 설정으로만 안내한다.

각 상태는 관측 근거로 산출한다. API 응답 성공만으로 원문 수집과 신선도까지 정상으로 처리하지 않는다. 수집 0건과 수집 실패, 정상 장 종료와 휴장, 원문 없음과 보존 장애를 구분한다. 원문·연구 기록과 재생 가능한 이벤트는 일반 캐시와 다른 보존 대상으로 다룬다.

중복 점검·갱신 버튼은 기능별 대표 위치 하나로 모은다. 고급 설정은 역할과 실제 변경 가능 여부에 맞춰 노출한다. 실행할 수 없는 설정은 입력창처럼 보이지 않게 한다. 동결된 콘텐츠 발행·성장 작업은 기본 메뉴에서 숨기되 데이터나 이전 URL을 삭제하지 않는다.

## 9 기술 구조와 비용

기존 수집기·가격·기업 근거·엔진 결과·개인 장부 위에 화면용 읽기 모델을 둔다. 하나의 버전 있는 스냅샷을 오늘 화면, 종목 상세, 시황 그림, 텔레그램이 공통으로 참조한다. 개인 보유 데이터는 사용자별로 결합하고 공용 캐시에 섞지 않는다.

읽기 모델은 `market_snapshot`, `company_context`, `portfolio_review`, `operations_incident` 네 책임으로 나눈다. company_context는 엔진 결론과 source facts, 해석, missing/stale reason을 구분한다. 각 응답에는 자료 기준시각·마지막 확인·스냅샷 버전이 있으며, 정성 근거는 사건 종류에 맞는 만료·종결 조건을 갖는다. 오래된 실적 보고서를 최신 뉴스처럼 표시하지 않으며, 미해결 공식 위험이 기간 경과만으로 소멸하지도 않게 한다.

첫 세 화면의 응답 초안은 [읽기 계약 JSON Schema](prototypes/signal-desk-v3-contract.json)에 기록했다. 시장 화면은 세션·가격 기준일·관측 범위·상승/하락/보합/제외 수·업종별 같은 기간 변화·미지 항목을 받는다. 종목 화면은 시그널 계산 시각과 커버리지, 출처 ID가 있는 긍정·반대·맥락 근거를 받는다. 내 투자 화면은 계좌 연결 방식·잔고 기준시각·통화·보유를 받는다.

상태는 `ready | partial | stale | unavailable`로 구분한다. 종가 기준일이 예상 거래일보다 뒤처지면 오늘 시장 판단과 현재 시그널을 만들지 않는다. 근거 문장은 원문 ID를 연결하며 발행시각과 우리가 실제로 알게 된 시각을 따로 기록한다. 이 계약은 구현 전에 조정할 읽기 모델 제안이며 현재 API가 이 필드를 보장한다는 뜻은 아니다.

현재 HTML은 화면별 JS 모듈·스타일·문구 사전으로 점진 분리한다. `today`, `stocks`, `portfolio`, `admin`, 공통 상태·요청·UI 구성요소로 경계를 둔다. API도 해당 읽기 모델을 별도 모듈로 추출한다. 특정 프레임워크로 전체를 재작성하는 일은 선행 조건으로 삼지 않는다. 기존 연구 및 주문 경로는 회귀 검증 대상으로 보존한다.

처음 보이는 요약 데이터만 먼저 받고 상세·차트·애니메이션은 사용 시 읽는다. 시장 전환 중 이전 요청 취소, 종목 키별 캐시, 중복 요청 합치기, 화면별 실패 상태를 제공한다. 시세와 뉴스와 거시지표에 같은 캐시 유효기간을 적용하지 않는다.

LLM 호출은 페이지 진입마다 하지 않는다. 새로운 근거 또는 시장 스냅샷이 의미 있게 바뀔 때 생성하고, 공용 결과는 같은 언어·시장·버전으로 재사용한다. 개인 잔고는 공용 이미지나 해설 프롬프트에 넣지 않는다. LLM 개입 없는 첫 화면도 완성된 상태로 제공한다.

월 비용은 텍스트 호출의 입력·출력 토큰, 이미지 생성 건수, 원천 API, 저장·전송을 각각 기록한다. 가격표가 고정되지 않은 상태에서 월 비용을 단정하지 않는다. 구현 첫 단계에서 실제 모델 단가와 예산을 확정하고 7일 사용량으로 재산정한다. 예산 초과 시 신규 장식 이미지 생성부터 중단하며 필수 데이터 조회와 신선도 알림을 우선한다.

3.0 초기에는 Milvus·별도 메시지 브로커·신규 ML 모델이 필요하다는 근거가 없다. 먼저 종목 식별·원문·시점·결론의 연결 품질을 확보한다. 검색량·지연·학습 표본이 실제 병목으로 관측되면 저장과 검색 계층을 확장한다.

### 가격·판단 시각의 공통 표시 · 2026-10-06 설계 추가

[2.0 기반 설계의 P1–P6](SIGNAL-DESK-2.0-ENGINE-FOUNDATION-DESIGN-2026-10-03.md#실시간-가격에서-판단매매까지의-기록-설계--2026-10-06)을 3.0 2·3·4·6단계의 공통 계약으로 연결한다. 사용자 화면에는 다음 세 가지를 같은 종목 카드에서 구분한다.

- **현재가:** 가격과 해당 종목 원천 기준 시각. 원천 시각이 없으면 “방금 수신 · 가격 기준 시각 미확인”으로 표시하며 실시간이라고 단정하지 않는다.
- **이번 판단:** “장중 가격 반영 · 10:05 판단” 또는 “직전 마감 기준 · 10월 6일 종가”와 판단 ID. 계산을 새로 했다는 사실이 가격도 새롭다는 뜻은 아니다. 날짜/시각은 표현 예시다.
- **다음 확인:** “현재가 갱신 지연으로 판단 보류”, “전일 종가 누락으로 추세 확인 필요”처럼 영향과 행동을 짧게 표시하고, 상세에서 수신 시각·누락 자료·재시도를 확인한다.

오늘 화면의 마감 시장 요약과 종목의 장중 가격은 각각 기준시각을 유지한다. 종목 카드·차트·알림은 동일 decision/input ID를 참조하고, 가격만 SSE로 새로 왔을 때 과거 점수의 계산시각까지 새로 바꾸지 않는다. 내 투자 주문 검토에는 판단 당시 가격과 새로 확인한 주문 가격을 따로 표시한다. 갱신 실패 시 과거 종가를 장중 체결 가능한 가격처럼 표시하지 않는다.

관리자는 한 장애 카드에서 `현재가 지연 / 일봉 공백 / 원천 시각 불명`과 영향받는 종목·보유·판단을 구분하고, 대상 한정 재조회와 실패 이유를 확인한다. 기존 Telegram outbox에 동일 장애와 복구를 연결한다. 이번 추가는 **설계만 반영**한 상태이며 P1–P6이나 3.0 단계의 구현·운영 검증 점수를 올리지 않는다.

첫 구현 범위는 “오늘에서 관심 종목 하나를 열고, 근거와 보유 맥락을 확인하는 흐름”이다. 여기서 사람들이 다음 행동을 설명할 수 있는지 확인한 뒤 계좌 도구와 이미지 표현을 확대한다.

## 12 실제 사용자가 검증할 과업

기존 피드백 참여자에게 개선 전후 같은 과업을 제시하고, 가능하면 처음 보는 사람도 별도로 관찰한다. 반복 참여에 따른 익숙함을 기록한다. 계좌 연결·주문 과업에는 허가된 데모 계정을 사용하고 실제 주문을 요구하지 않는다. 기존 공식 자료 이해도 평가의 운영 사례 요건은 해당 평가에 그대로 적용한다.

1. 오늘 국내 시장의 특징과 근거 하나를 30초 안에 찾아 설명한다.
2. 관심종목에서 긍정 근거와 우려를 찾고 원문으로 이동한다.
3. 현재 매수 후보와 상승 확률 보장의 차이를 설명한다.
4. 내 투자에서 손익 기준과 마지막 계좌 확인 시각을 찾는다.
5. 한 종목에 추가할 때 비중이 어떻게 바뀌는지 미리 확인하고, 주문이 아직 실행되지 않았음을 이해한다.
6. 배당의 확정액과 추정액을 구분한다.
7. 관리자가 시세 지연의 영향과 다음 조치를 찾는다. 이 과업은 일반 사용자 평가와 따로 기록한다.

출시 목표 초안은 일반 과업별 5명 중 4명 이상이 도움 없이 완료하고, 실제 주문 여부·과거 자료의 현재성·후보 등급의 의미에 위험한 오해가 있으면 수정 뒤 다시 확인하는 것이다. 이는 소규모 사용성 검증이며 모집단 전체의 학습 효과를 입증하지 않는다. 점수가 낮으면 사람을 교체해 통과시키지 않는다.

성능 목표 초안은 핵심 화면 LCP p75 2.5초 이내와 모션·이미지 생성의 본문 로딩 비차단이다. 현재 측정치는 아니며 구현 전에 장치·망·캐시 상태와 측정 방법을 고정한다. 사용성 목표와 투자 수익 개선은 별도로 측정한다.

## 13 유지하는 연구와 운영 조건

등록 헤드라인의 문턱·표본·최악 위상 조건, 퀄리티 가중치 0.15, 연구 전용 전략과 가중 게이트 잠금을 변경하지 않는다. 초기 이미지·해설·통합 화면은 주문 판단을 바꾸지 않는다. interim/final 조기 실행, 5년 가격 백필, 누락 봉 보간, 과거 미국 구성 되메우기, 성장·숏폼 동결 해제는 이번 설계에 포함하지 않는다.

2026-10-05에 [세 화면 클릭형 시안](prototypes/signal-desk-v3.html)을 추가했다. 오늘→종목 이동, 국내·해외·관심 필터, 기업의 긍정·우려·자료 대기 상태, 내 보유·계좌·배당 동선을 가상 자료로 확인할 수 있다. 실제 종목·계좌로 오인하지 않도록 모든 화면에 시안·가상 자료임을 표시했다. 이 시안은 제품 코드나 운영 API에 연결되지 않는다.

시안에 기존 hash 경로의 목적을 옮기는 예시를 연결했다. `#signal`·`#watchlist`는 종목으로, `#trading/*`는 내 투자로, `#cycle/*`는 오늘 또는 관련 종목 설명으로 이어진다. 관리자와 계정 설정은 기존 권한을 지켜 프로필 공간에 남긴다.

읽기 계약 JSON Schema와 URL 대응표, 문구 기준을 추가했다. 시안 HTML에는 오늘→종목→내 투자 클릭 흐름과 가상·자료 대기 상태가 있고, 계약에는 ready/partial/stale/unavailable 상태가 정의돼 있다. 브라우저 보안 정책 때문에 미리보기 렌더는 직접 확인하지 못했으며 다른 경로로 우회하지 않는다. 렌더 검토는 잔여 확인사항으로 남기되 1단계 표의 완료 기준은 충족한 것으로 계산한다. 사용자 재평가는 8단계 완료 조건이다.

### 구현 현황 · 2026-10-05

- 1단계 완료(10/100): 클릭 가능한 세 화면 시안, 읽기 계약, 기존 URL 대응, 문구 기준을 마련했다. 실제 앱 전환과 사용자 재평가는 후속 단계 범위이며 브라우저 렌더 확인은 남은 품질 확인사항이다.
- 2단계 착수: 시장 카드에 직전 거래일 종가와 이어지는 종목만으로 당일 상승·하락 수, 중앙 변동률을 분리 계산한다. 국내는 기존 큐레이션 업종표에서 3개 이상 관측된 업종만 상대 흐름을 보이며, 해외 업종 분류는 기준시점 확인 전까지 보류한다. 화면 요약과 SVG가 중기 평균 위치만으로 오늘의 방향을 단정하지 않게 했다.
- 이 진단은 현재 관찰 유니버스의 설명용 읽기 모델이다. 거래소 전체 지수, 미래 방향, 매매 입력으로 표현하지 않는다. stale 종가·부족한 직전 거래일 종가는 오늘 방향에서 제외하거나 보류한다.
- 아직 남음: 운영 환경과 기준일 대조, 시장별 상승 범위·업종 분류 근거 확인, 장중/휴장/자료 누락 사례의 사실 일치 검증. 따라서 2단계도 미완료다.
- 3단계 선행 구현: 종목 상세 응답에 사용자별 읽기 전용 `company_review`를 붙였다. 가격 판정과 확인된 DART 위험, 최근 귀속 확인 뉴스, 분석용 보유 입력을 한 화면에서 나란히 보여준다. 원문 ID·발행/관측시각을 붙이고, 확인된 기사도 상승·하락 표로 임의 분류하지 않는다. 동일 제목 재인용, 낡은 기사, 실패·오래된 수집 확인, 만료된 공식 사건은 현재 근거에서 제외한다. 장중 잠정가와 확정 종가를 분리하며 오래된 장중 시세는 현재 판정으로 재표시하지 않는다. 이 응답은 `private, no-store`이며 점수·주문 경로에는 연결되지 않는다.
- 3단계 남음: 운영 원문의 회사 귀속·중복·정정 공시 사례 대조, 긍정적 사업 변화와 공식 위험을 함께 읽는 실제 사례 점검, 사용자 과업 확인. 특히 현재 뉴스는 검증된 기사 제목을 `맥락`으로만 보여주며 긍정 근거로 단정하지 않는다. 이 증거가 끝나기 전에는 3단계 20점을 합산하지 않는다.

### 2단계 후속 구현 · 2026-10-06

- 운영 화면에서 국내 200/200종목은 107상승·89하락·4보합으로 표시됐고, 미국 503종목 중 직전 거래일과 비교 가능한 종목은 275개뿐이었다. 미국 카드의 기존 대표 문구 “오늘은 오른 종목이 더 많았어요”는 부분 관측을 시장 전체로 오해하게 할 수 있었다.
- 화면 설명용 방향 판단은 **직전 거래일과 이어지는 종가가 관찰 유니버스의 80% 이상**일 때만 제목에 낸다. 80% 미만이면 상승·하락 수는 근거로 남기되 대표 문구는 자료 부족으로 보류한다. 80% 이상이어도 일부가 빠졌으면 제목에 실제 확인 종목 수를 붙인다. 이 경계는 투자 엔진의 국면·가중치·주문 규칙과 무관하다.
- 별도 `#today` 화면을 만들어 시장 요약만 먼저 읽고 `종목 보기`로 이어지게 했다. 기존 `#signal` 북마크와 목록은 유지한다. 오늘 첫 진입에서 숨겨진 종목 목록·계좌 화면을 선요청하지 않도록 분리했다.
- 국내·미국의 실제 배포 화면, 장중·휴장·자료 누락 상태를 새 동선에서 대조하기 전에는 2단계를 완료로 세지 않는다. **3.0 진행률은 10/100점(10%) 그대로**다.

### 2단계 운영 대조 · 2026-10-06 저녁

### 3단계 시세 시각 안전장치 · 2026-10-06

- 종목 상세의 장중 잠정가와 목록의 SSE 현재가가 전 종목 공통 마지막 성공 시각을 사용했다. 일부 보유 종목만 1분 갱신되면 다른 종목의 오래된 가격도 함께 새로워 보일 수 있었다.
- 종목별 마지막 성공 시각을 보존하고, 상세의 현재 판정 및 차트 시각은 해당 종목 시각만 읽는다. 목록도 10분이 지난 장중 가격을 현재가로 표시하지 않고 `현재가 갱신 지연`으로 바꾼다. 이 변경은 가격 데이터와 화면의 시각 표기이며 시그널 점수·주문 규칙을 바꾸지 않는다.
- 운영 장중에서 일부 종목 갱신 실패를 실제로 관측해 대조하기 전에는 3단계 완료 점수를 합산하지 않는다.
