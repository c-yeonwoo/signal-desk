## 3. 기존 경로에 바로 넣으면 안 되는 이유

아래는 기준 코드의 확인 결과이며 이번에 수정하지 않았다.

- `external_watch.add_items`는 종목 중심 메모다. 같은 종목의 과거 출처가 덮어써질 수 있고 회사명 유사 검색은 게시글 식별 원장으로 부족하다.
- `external_watch.kb_priority_targets`는 호출부가 없다. 기존 `api._kb_targets`의 수집 범위/비용 제한 때문에 외부 후보 등록만으로 원문 수집이 자동 보장되지 않는다.
- `db.kb_document_add`는 같은 URL을 갱신하고, `kb_search._build`는 모든 문서를 읽는다. `pending`으로 넣는 것만으로 검색·가설 경로에서 격리되지 않는다.
- `kb.sync_candidate_events`에는 부정 근거가 매수 차단/청산 후보로 이어지는 경로가 있다. 외부 의견을 기존 KB에 바로 넣으면 설명 전용이라는 경계가 깨질 수 있다.

따라서 **별도 연구 원장과 명시적 읽기 경로**를 먼저 만든다. 기존 후보 화면을 재사용할 수 있지만 원장·검증 상태는 기존 점수나 주문과 분리한다. 새 메뉴·벡터 DB·상시 다중 LLM부터 추가하지 않는다.

## 4. 원장과 사실 검증 계약

`external_ideas`의 기본 단위는 종목이 아니라 **원 작성자 + 게시글 + 버전 + 주장**이다.

| 필드군 | 필수 내용 |
|---|---|
| 출처 | 플랫폼/계정 ID, 원문 ID·URL, 집계기 ID·URL, 수집 방식·이용 권한 |
| 버전·시간 | 원문 공개 시각과 정밀도, 최초 관측, 집계기 기준 시각, 추출 완료, 검증 완료, 내용 해시, 정정/삭제 연결 |
| 증권 | 거래소·증권 ID·주식종류, 티커 당시 유효성, 주식/옵션 등 상품 구분. 애매하면 미매핑 |
| 해석 | 언급/주장/매수 의향/보유 공개 구분, 방향, 원문 구절 위치, 보유 지평·무효화 조건. 미기재는 unknown |
| 검증 | 사실·추론·추측 분리, 공식 반증/지지 원문, 근거 가용 시각, 동일 상류 주장 ID, 검수 상태 |
| 격리 | `live_order_eligible=false`, `registered_verdict=false`, 정책/추출기 버전, 가정과 제외 이유 |

같은 글 재수집은 중복 호출하지 않고 새 버전은 별도로 저장한다. 오래된 내용을 오늘 재수집했다고 최신 의견으로 갱신하지 않는다. 수정·삭제 흔적과 원문 미확보를 표시하되 이용 약관의 보존/삭제 요구가 우선이다. 보관이 허용되지 않으면 원문을 삭제하고 허용 범위의 tombstone만 남긴다.

LLM은 구조화 추출과 확인할 질문 작성까지만 한다. 스키마 검증·원문 위치·회사 귀속 확인에 실패하면 abstain한다. 원문의 지시문은 실행하지 않는다. 공식 IR·공시로 확인된 **사실**도 별도 승인된 변환 없이는 주문 경로에 넣지 않는다. SEC 자동 요청은 기존 연락처 관문을 유지한다.

## 5. 비교 실험: 복사와 조합을 둘 다 시험한다

결과를 보기 전에 저자·기간·수집 범위·지평·자금·비용·진입/청산·결손 규칙을 manifest로 고정한다. 우선 연구는 현물 롱으로 한정한다. 옵션 보유 의견을 현물로 대용하면 `stock_proxy`라고 쓰며 저자의 전략 재현으로 부르지 않는다.

| 실험군 | 후보와 판단 | 알아낼 것 |
|---|---|---|
| E | 동결 현행 엔진 | 기존 기준선 |
| X | 원문의 명시적 투자 의향 + 사전 고정 실행 규약 | 의견 추종 가설 자체의 비용 후 가치 |
| H | 외부에서 발견한 후보 + 공식 사실 검증 + 고정된 엔진/실행 규약 | 외부 조사와 엔진 결합의 추가 가치 |
| N | 비거래 및 시장·업종 대조 | 시장 상승·업종 집중을 실력으로 오인했는가 |

동일 자금·보유 한도·시각·비용·매도 규칙으로 비교한다. X의 미언급 청산은 미리 고정한 시간/위험 규칙을 쓰며 저자가 실제 매도했다고 기록하지 않는다. 원래 후보군 안의 공통 표본 비교와, 사전 규칙으로 확장한 후보군 비교를 분리하여 **종목 풀이 넓어진 효과와 선정 능력 개선**을 구분한다. 미지원 증권·비유동·결손을 전체 분모에서 삭제하지 않는다. 기존 개발 창·등록 보호 구간을 새 OOS라고 재활용하지 않는다.

시점은 두 모드다.

1. `reconstructed_public`: 그 시점 원문 버전·공개시각이 확인된 과거 자료만. 당시 우리 수신을 주장하지 않고 집계/처리 지연 가정을 명시한다. 공개 날짜·시간대는 있고 시각만 없으면 해당 공개일 마지막 순간을 가용시각 상한으로 두고 그 뒤 다음 정규장부터 사용한다. 날짜·버전·공개시각의 상한조차 증명하지 못하면 이 모드에서 제외하고 최초 수신 이후 `observed`로만 다룬다. 장중 데이터가 없으면 당일 최저가·게시 직후 체결을 가정하지 않는다.
2. `observed`: `max(원문 가용, 최초 수신, 추출 완료, 해당 실험군 필수 검증 완료)` 이후 실제 가능한 다음 호가/봉을 사용. 집계기의 1시간/3시간 지연과 원문 지연을 별도 기록한다.

긴 투자 논지를 하루 수익으로만 채점하지 않는다. 원문 지평의 가설 검증과 단기 실행 수익을 분리한다. 단기 지평의 수치는 손익 라벨이지 원문의 장기 가설 참/거짓 판정이 아니다.

우선 지표는 추가로 찾은 후보 수, 잘못 연결한 회사/주장 비율, 원문 가용성과 지연, 누락·삭제·정정 비율이다. 이어 비용 후 수익, 최대 역행·낙폭, 회전율, 미체결, 업종 집중, 실패 사례를 낸다. 날짜·저자·공통 주장 묶음의 상관성을 고려한 불확실성 구간을 사용하고, 저자 선정과 성과 채점 기간을 분리한다. 전수 기록이 없으면 **확보된 글 집합의 연구**로만 보고하며 계정 전체 승률을 발표하지 않는다.

E와 H의 비교는 외부 후보와 공식 검증의 결합 효과다. 같은 후보에 검증 유무만 바꾸는 별도 대조 없이 공식 검증 자체의 수익 기여도를 주장하지 않는다.

새 가설·추출기 변경은 버전을 올려 다음 미사용 평가 구간으로 넘긴다. 결과가 좋아질 때까지 같은 표본을 반복 최적화하거나 자동으로 운영 가중치를 학습하지 않는다. 구체적 표본과 합격 기준은 실제 접근 가능한 코퍼스를 확인한 뒤 **수익 결과 열람 전에** 별도 등록한다. 현재 문서는 실험 실행/승격 승인서가 아니다.

## 6. 접근·비용·화면

[Capafy 약관 §6.2·§7.4](https://capafy.ai/terms-of-service)는 자동 접근·체계적 수집과 출력물 라이선스에 조건을 둔다. 구독만으로 자동 피드·재배포·모델 학습 권한을 얻는다고 가정하지 않는다. 허용된 직접 원문 링크나 사용자가 제공한 자료의 권한을 확인해 작은 파일럿부터 시작한다. 공개 설명의 링크 검토와 유료 보고서 대량 적재는 별개다.

공개 홈페이지와 상품의 교차 추천 가격 표기가 달라 실제 청구 주기·총액은 결제 단계 확인 전 확정하지 않는다. 이번에는 결제하지 않았다. 원천 구독/API, 추출 토큰, 공식 검증 요청, 저장을 분리 계측한다. 수집/추출 횟수·토큰·금액 상한이 설정되지 않으면 자동 작업을 실행하지 않는다. 신규 버전만 추출하고 공식 검증은 선택된 후보에만 수행한다. 유료 제공자 추가는 별도 승인한다.

기존 연구 후보 화면에는 `누가 왜 주목했나 / 원문·작성·확인 시각 / 우리 판정 / 확인된 사실·반대 근거 / 다음 확인 조건`만 짧게 보여준다. `외부 의견·검증 중`과 현재 엔진 판단을 구분한다. ‘3명 추천’은 원문이 독립인지 확인되지 않으면 신뢰도 점수가 아니다. 단기 경보는 별도 시세 탐지기가 맡으며 시간 단위 집계만으로 속보 대응을 보장하지 않는다.
