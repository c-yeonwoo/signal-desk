# Signal Desk — 수익·신뢰·사용성 통합 재설계 로드맵

작성: 2026-09-27 · 검토 기준: `main@b6e36c8` (PR #446 병합 후)

## 1. 결론과 범위

추천 방향은 **지표와 AI 판단을 더 많이 붙이는 봇**이 아니라, **검증된 투자 가설을 사용자의 위험예산 안에서 비용 효율적으로 집행하고, 결과를 설명하는 투자 운영 시스템**이다.

당장 우선순위는 `실행 결함 → 성과 측정 → 판단·배분 통합 → 저회전 전략 실험 → 차별화 데이터 전략`이다. 현재 수익 부진을 새로운 팩터로 덮으면 원인을 구분할 수 없고, 좋은 팩터도 잘못된 주문 경로와 청산 규칙 때문에 손실로 바뀔 수 있다.

이번 작업은 코드·실제 운영 UI·해외 원문을 대조한 **진단 및 구현 계획**이다. 매매 규칙, 운영 스위치, 계좌 설정을 변경하거나 실주문하지 않았다. 아래 재현은 외부 자격증명을 비운 임시 디렉터리의 가상 계좌에서 수행했다. 새로운 전략의 수익률 백테스트는 수행하지 않았다.

- 목표: 비용 차감 후 장기 복리성과를 높이되, 사용자 손실·집중도·현금·주문금액 한도를 지킨다.
- 적중률·거래 횟수·앱 접속 횟수는 보조지표다. 위험을 늘린 결과를 알파 개선이라고 부르지 않는다.
- 복수 계좌, 환율 통합, 개인별 세금 최적화는 제외한다. 거래비용 계상과 KRW/USD 분리 표시는 필요하다.
- 이미 구현한 기능은 재사용한다. 전면 재작성이나 새 프레임워크로의 일괄 이관은 권하지 않는다.
- 9월 24일 연구안의 B(체결비용), A(리비전), E(포트폴리오), C(관계망), D(수급반전)를 유지하되, 이번에 확인한 실행·측정 결함을 그 앞에 추가한다.

## 3. 우선 수정할 문제: 전략보다 앞선다

### P0-A. 매수 경로마다 다른 안전·위험 정책

`src/signal_desk/bot.py:663`의 `slots=0`은 최초 매수 블록만 차단한다. `:832`의 교체 조건에는 `sells_only`가 없고, `:840` 이후 ADD 루프는 별도로 돈다. `:1071`의 예약 실행도 독립 경로다.

임시 페이퍼 계좌에서 기존 `tests/test_bot.py`의 `_setup/_seed`를 사용해 확인한 결과:

| 조건 | 기대 | 현재 재현 결과 |
|---|---|---|
| `sells_only=True`, 목표비중 미달 보유 | 매수 0 | ADD 2주 가상체결 |
| 일일 손실 한도 초과 | 위험 증가 0 | ADD 2주 가상체결 |
| 현재 투자액이 노출 상한 초과 | 위험 증가 0 | ADD 2주 가상체결 |
| `sells_only=True`, 슬롯 가득 참, 교체 가능 | 교체 매수 0 | ROTATE_IN 5주 가상체결 |
| kill switch 활성, 예약 대기 | 주문 0 | RESERVATION 8주 가상체결 |

`api.py:236`의 빠른 경로는 `r.sells`가 있을 때만 거래 알림을 보낸다. 따라서 의도하지 않은 ADD만 발생하면 알림도 누락될 수 있다. 최초 매수 성공 테스트나 알림 포맷 테스트만으로 이 결함을 잡지 못한다.

수정안:

1. `NEW / ADD / ROTATE_IN / RESERVATION / COPY`가 모두 동일한 `authorize_risk_increase(intent, snapshot, policy)`를 통과하도록 한다.
2. 현금·수수료·미체결 예약금·일일 한도·포트폴리오 한도·유효시각을 마지막 제출 시점에 다시 확인한다.
3. hard halt(모든 주문 중지)와 risk-increase halt(위험 증가만 중지)를 분리한다. hard halt를 무시하고 매도하는 식으로 바꾸지 않는다.
4. 예약은 과거의 허가증이 아니다. 실행 때 신선한 시세와 현재 포지션, 이벤트·한도·만료를 재검사한다.
5. 주문 결과 이벤트에서 알림을 만들고, 빠른/느린 호출자가 매수·매도 알림 여부를 따로 판단하지 않게 한다.

이 재현은 **페이퍼 경로**다. 토스 수동 주문은 `broker/toss_manual.py`의 별도 검사를 거치므로 같은 실주문 우회가 확인됐다고 말할 수 없다. 다만 추종 기준 봇의 원장 신뢰에 직접 영향을 준다.

### P0-B. 거래소 세션과 시스템 날짜의 불일치

`bot.is_market_hours()`는 주말만 제외하고, 미국 시간도 KST 근사 구간이다. `api._open_markets()`가 이를 사용한다. `store.signal_drift()`는 이력 날짜를 그대로 비교한다. 한편 수동 토스 주문과 일부 연구 모듈은 더 엄격한 달력을 이미 사용한다.

- 단일 `MarketClock`에서 XKRX/XNYS 세션, 서머타임, 조기마감, 장전·장후, 증권사 당일 운영정보를 구분한다.
- `observed_at`(UTC), `exchange_session`, `bar_asof`, `decision_at`을 별도 저장한다.
- 휴장일에는 수집 시도 기록은 남기되, 동일 종가를 새 거래일의 증거·분할매수 기회로 만들지 않는다.
- 동결 경고는 ‘새 거래 세션의 입력이 갱신되어야 했는데 안 됐는가’로 판정한다.
- 기존 휴장일 가상체결·중복 스냅샷은 삭제하지 않는다. 원장을 보존하고 `session_invalid` 등 품질 플래그와 정정 계산 버전을 추가한다. 당시 유효한 시세·의도가 없는 구간을 임의의 다음 날 체결로 복원하지 않는다.

설치된 `exchange-calendars==4.13.2`로 2026-09-23은 세션, 24·25는 비세션임을 확인했다. [KRX 추석 운영 공지 목록](https://strn.krx.co.kr/corebbs5/BHPSTRN0401/list)도 9/24~9/27 연휴를 안내한다. 운영 체결이 실거래소 체결이었다는 뜻은 아니다.

### P0-C. ‘성과 확정’ 계산을 먼저 정정

`bot.harm_alert():1214`는 시장의 전체 기간 수익률을 블록 수로 나눈 **상수**를 매 블록의 봇 수익에서 뺀다. 실제 동기간 시장 경로와 공분산을 사용하지 않으므로 초과수익 오차 추정이 맞지 않을 수 있다. 복리수익을 단순 합으로 환산하고, 블록 관측도 자동으로 독립이라고 취급한다. 이를 근거로 UI가 ‘확정’이라고 말하는 것은 과도하다.

`benchmark_return_pct():939`는 현재 유니버스로 과거 기간을 계산한다. 당시 구성종목이 아니며, 배당·기업행사·중도 편출입의 처리도 일치 여부를 확인해야 한다. `performance()`는 현재 평가액과 저장된 곡선 끝의 기준선을 섞을 수 있고 MDD는 시드 시작점을 포함하는지 점검해야 한다.

개선:

- 동일 세션·가격관례의 봇/시장 수익률 **쌍**을 만들고, 상대 NAV 및 paired block bootstrap/HAC를 사용한다. 블록 길이와 추론 대상은 사전 정의한다.
- 시장 추종 대안, PIT 동일가중, 같은 현금/위험예산 기준선을 분리한다. 시장 대비 부진을 현금으로 숨기지도, 현금 방어를 종목선별 알파로 포장하지도 않는다.
- 보유종목 손익 / 페이퍼 순자산 수익 / 실제 계좌 TWR / 시그널 h5·h20 / 모델 상대효과는 별도 지표다.
- 현재 실계좌 관측은 `account_performance.py`에 명시된 `holdings_only`다. 현금·입출금·실현손익·배당/기업행사 원장이 갖춰지기 전에는 계좌 TWR라고 이름 붙이지 않는다. 우선 KR 단일 통화부터 확장한다.
- 복원 불가능한 과거는 `unknown`과 커버리지로 남긴다. 기존 가상거래 기록을 바꾸어 성적을 개선하지 않는다.

### P1. 판단 의미·시장 맥락·운영의 분리

- `engine.py:848`의 confidence는 `abs(2*sigmoid(score)-1)` 변환이지 보정된 수익확률이 아니다. 당장은 ‘점수 강도’로 구분하고, 향후 OOS calibration을 통과한 값만 확률로 표시한다.
- `bot.run_once()`는 US 실행 때도 KR 가격에서 만든 `mr`를 노출·청산 국면에 사용한다. 글로벌 거시 공통 사용과 국내 breadth의 미국 전용은 다른 문제다. 시장별 정책 맥락을 명시하고 분리 비교한다.
- 진입 때 저장한 risk와 이후 매 틱 재계산한 변동성·국면 risk의 관계를 명시한다. 진입 고정 또는 적응형 중 하나를 정책 버전으로 정하고, 적응이면 변경 이벤트까지 재생한다.
- 정성 점수의 ‘shadow/봇 미반영’ 문구와 달리, 활성 advisor는 KB digest를 입력받는다. **직접 점수 반영과 LLM 간접 선별 영향**을 구분해 표시·실험한다.
- `api.py` 약 5천 줄, `index.html` 약 9.5천 줄. 크기 자체보다 주문·연구·수집·설명 UI가 함께 바뀌는 것이 문제다.
- 프로세스 임대는 같은 프로세스의 빠른/느린 틱을 직렬화하지 않는다. `paper.place_order()`의 load→수정→save와 다른 쓰기의 경쟁은 별도 재현해야 한다.
- `notify.push()`는 한 채팅 성공만으로 전체 성공을 반환하고, outbox 조회에 독점 claim이 없다. 수신자별 재시도와 원자적 lease를 추가한다. Telegram 전송 직후 프로세스 종료 같은 경우의 완전한 exactly-once는 보장하지 않는다.

## 5. 수익 개선 전략: 순서와 반증 조건

모든 신규 전략은 **가설**이다. 아래 순서는 예상 수익률 순위가 아니라 현재 데이터와 구현 비용을 고려한 연구 우선순위다.

### S0. 수익 누수 억제: 비용 인지 보유·교체

가장 먼저 할 실험이다. 새 정보를 추가하지 않고 같은 후보에서 순수익을 더 남길 수 있는지 묻는다.

- ‘신규로 살 만큼 좋은가’와 ‘이미 가진 것을 팔 만큼 나빠졌는가’의 문턱을 분리한다.
- 고정 score gap 대신 교체 후 예상 순이익, 추정 오차, 위험 변화, 왕복비용을 비교한다. 초기에는 미보정 점수를 수익률로 환산하지 않고, 사전등록한 순위 buffer/주기만으로 비교한다.
- `매매하지 않음`과 `현재 보유 유지`를 명시적 선택지로 넣는다.
- 손실 중이라 교체 대상에서 자동 제외하는 현행 `max_loss_pct`는 재검토한다. 매입가가 아니라 앞으로의 기대·위험·비용으로 판단하되 강제 손절 규칙은 별도로 둔다.
- h20 가설을 5분 가격 흔들림으로 계속 청산하지 않도록, **위험 청산**과 **알파 만료/약화에 따른 청산**을 구분한다.
- 무효화 조건: 회전은 줄었지만 비용 후 수익이 개선되지 않거나, 위험예산·큰 손실·회복기간이 악화됨. 낮은 거래 수 자체는 성공이 아니다.

#### R11: 회전 판단·전진 가격을 동결한 shadow (`rotation-shadow-s0-v2`)

- 마감 1시간 뒤 동일한 레퍼런스 봇 잔고·시장별 PIT 시그널·동일 세션 종가를 최초 1회 SQLite에 보존한다. 한국 12시간/미국 20시간을 넘겨 지연된 관측은 현재 보유를 과거 보유로 재구성하지 않고 버린다(미국 조기마감 뒤 KST 15:40 스냅샷 허용). 미국은 독립 미국 PIT 스냅샷 세션이 일치해야 한다. PIT-종가 정렬이 95% 미만이거나 상위 신규 후보/해당 보유의 가격 날짜가 다르면 제외하며, 비상위 결손 종목은 그날의 후보에서 빼고 목록에 명시한다. 관리자 ‘엔진 검증 → 저회전 정책 비교’ 또는 읽기 전용 `/api/admin/research/rotation-shadow?market=kr&style=balanced&include_inputs=true`에서 동결 입력과 두 결정을 볼 수 있다.
- 챔피언 쪽은 기존 `ROTATION_PRESETS`의 후보·보유·score gap/손실 제외/보유기간/쿨다운을 **종가에서 재현한 회전 프록시**다. 실제 장중 주문을 재생한 것으로 취급하지 않는다. 양쪽 모두 동일한 슬롯 조건·투자경고·재매수 쿨다운을 적용한다.
- 챌린저는 신규 후보 상위 3%와 계속 보유 상위 10%를 구분하고, 각 ISO 주의 첫 관측 거래일에만 검토하며 최소 5개 종가 세션을 보유한다. 매입가 대비 손실 여부는 제외 조건이 아니다. 순위 완충 외의 점수 차를 예상 수익으로 환산하지 않는다. 파라미터는 결과를 보기 전에 이 버전으로 고정한다.
- 판단 시점 가격과 비용 모델로 각 정책의 **정수주 수량을 먼저 동결**한다. 다음 거래일 종가에 동일 수량으로 가상 체결(가격 갭으로 현금이 부족하면 비교 보류)하고, 동일 초기 자본·동일 20개 거래일의 가격을 최초 관측 시점에 저장한다. 전진 관측창에서 최초 판단 종가나 저장된 전진 가격이 수정·삭제된 사실을 발견하면 그 에피소드는 영구 보류한다. 중간 가격을 놓치면 전일가 대체·나중 백필 없이 보류한다. 5/20거래일 비용 후 수익차, 비용 드래그, 거래금액/초기자산, 최대낙폭을 각각 표시한다. `v1`처럼 수량을 동결하지 않은 과거 에피소드는 사후 재구성하지 않는다. 관측창 이후 가격 재작성의 전수 재감사는 아직 없으므로, 결과는 원천 데이터 확정성과 함께 잠정으로 읽는다.
- **이 단계는 주문에 연결되지 않으며 승격·수익 개선을 주장하지 않는다.** 위험 청산, 신규 편입, 분할매수, 실제 매수 한도/체결 실패, 배당·기업행동과 호가는 비교 밖이다. 종가 원천의 최종 확정 메타데이터도 없다. 에피소드들이 날짜·보유종목을 공유하므로 이 수익차를 합산해 전략 트랙레코드로 주장할 수 없다. 충분한 비중첩 OOS 표본과 동일 위험예산/낙폭 판정이 쌓이기 전에는 챔피언 승격 불가.

#### R11 사전등록 판정 게이트 (`r11-s0-rotation-oos-v1`)

- 시작일 `2026-09-28` 이후의 `v2` 동결 에피소드만 사용한다. 주요 지평은 **다음 거래일 종가 가상 진입부터 20거래일**이고, 5거래일은 진단용이다. 같은 시장·성향에서 두 정책의 고정 주문이 다른 날을 날짜 오름차순으로 고르고, 직전 선택 에피소드의 20일 평가 종료일까지는 새 블록을 뽑지 않는다. 가격/성과를 보기 전에 날짜로 선택하며, 누락·가격수정 블록을 나중의 겹치는 좋은 표본으로 대체하지 않는다.
- 통계 판정은 비중첩 성숙 블록 수 **12·24·36·48**에서만 갱신한다. 양방향(우위/열위)×KR/US×3성향×4회 look의 다중 판정을 고려해 가족오류 5%를 48로 나눈 단측 수준을 사용한다. 비중첩 블록의 비용 후 h20 차이 평균을 고정 시드 10,000회 재표본해 하한/상한을 계산한다. 이는 시장국면 간 독립성까지 보증하는 정리가 아닌 근사 구간이다.
- 사전 선택 블록의 완료·무결성 커버리지 90% 이상 및 유효 12블록 이상이 기본 전제다. 비용 후 차이의 보정 하한이 0을 넘어야 하고, 저회전의 평균 거래금액/초기자산과 평균 비용 드래그가 모두 낮아야 한다. 평균 최대낙폭 악화는 1%p 이하, 어떤 한 블록의 악화도 3%p 이하라야 한다. 하나라도 빠지면 `manual_review_candidate`가 아니다.
- `manual_review_candidate`는 전략 승격이 아니다. 종가 프록시와 실제 봇의 장중 청산·신규매수·미체결을 대사한 동일 위험예산의 전체 정책 검증, 원천 가격 확정성, 수동 승인 없이는 챔피언/실주문 정책을 변경하지 않는다. 임계나 look 변경은 새 버전의 **새로운 미래 표본**으로만 한다.

### S1. 단순하고 강한 대조군: 중기 상대 모멘텀

- 현재 3개 가격 팩터 전략을 기본 대조군으로 고정한다. 기존 6팩터 조합이 더 좋다고 가정하지 않는다.
- 시장·섹터 대비 상대수익과 추세 지속성을 이용한 중기 후보를 한 가지 고정 사양으로 만든다. lookback·최근 반전 구간 제외·재조정 주기는 탐색/검증을 분리해 등록한다.
- quality(수익성·현금흐름·재무건전성)는 우선 제외 필터 또는 위험 조정으로 비교한다. 밸류는 같은 업종·회계 특성에서 비교하고, 적자기업 비율 문제를 회피한다.
- 200종목 유니버스의 작은 섹터 집단에는 무리한 섹터 z-score를 쓰지 않는다. 최소 표본 미달은 시장 기준으로 축소하거나 기권한다.
- 주식 익스포저가 낮은 이유가 의도한 방어인지 후보 부족/정수주 때문인지 분해한다. 후보 확대나 ETF 보완을 하더라도 별도 검증·사용자 선택이다.
- 무효화 조건: 비용 후 단순 대조군을 못 이김, 특정 섹터/몇 종목을 빼면 효과 소멸, 현금·베타 조정 후 이점 소멸.

#### R12a 전진 가격 대조군 (`r12-s1-price-v1`, 주문 미연결)

- 매일 한국/미국 각각 마감 1~12/20시간 창에서 **해당 공식 거래 세션의 PIT 시그널·원시 종가가 맞는 종목만** 첫 관측으로 동결한다. 미국은 독립 US PIT 스냅샷 세션 일치가 필수다. PIT 모멘텀(소수점 4자리)과 원시 252/21거래일 수익률도 일치해야 한다. 50종목 미만 또는 유효 종목 95% 미만이면 그 세션은 기권한다. 원천 종가의 최종 확정 메타데이터는 아직 없다.
- 기준은 현재 `SignalConfig`의 `_price_only_components`/`combine`으로 계산한 **가격 3팩터 점수** 상위 3%(동률은 종목코드)다. 이는 전체 8팩터 라이브 시그널이나 봇 주문의 재현이 아니다. 후보는 `12-1` 모멘텀 원수익률이 양수인 종목만 대상으로, `원수익률 − [시장 중앙값 + n/(n+10) × (섹터 중앙값−시장 중앙값)]` 상위 3%다. 섹터 PIT 종목 수가 5 미만 또는 미분류이면 축소계수는 0으로 한다. 섹터 평균만 빼고 순위가 같다고 주장하지 않도록 실제 순위/종목 변경을 표시한다. 현재 KR 수동 섹터 분류와 US 유니버스 섹터는 그날 함께 동결한다.
- 두 정책의 선택 종목을 같은 관측 창에 보존한다. 같은 시장에서 이전 20거래일 평가창이 끝나기 전에는 새 에피소드를 동결하지 않는다. 평가용 가상 원금은 KR 1억원/US 10만달러로 **계좌 금액과 무관**하다. 각 정책 동일 `top_k` 슬롯·동일 원금/거래비용·판단일 종가 기준 정수주 수량을 고정하고 다음 거래일 종가 가상매수, 20번째 거래일 종가 가상매도 후 비용 후 수익률을 비교한다. 다음날 갭으로 현금이 부족하면 양쪽 비교를 보류한다. 체결 불가능한 슬롯은 현금으로 남긴다.
- 진입/청산 종가가 최초 관측 시각에 없으면 나중 백필하지 않는다. 저장된 판단/진입/청산 가격이 재수집에서 바뀌면 영구 보류한다. 최근 에피소드만 재감사하므로 장기 가격 최종성은 여전히 미보증이다. 배당·분할/기업행동·호가/시장충격·실체결·세금·장중 위험청산은 비교 범위 밖이다.
- 관리자 `엔진 검증 → 가격 전략 대조군` 또는 읽기 전용 `/api/admin/research/price-baseline`에서 시장별 입력/상태/비용 후 차이를 본다. 이 PR은 prospective 수집·채점 인프라이고 표본 우위/승격 판단이 아니다. quality 증분은 다음 버전에서 **별도 축**으로 비교한다. 시장·베타·섹터·현금·이상값 민감도 및 비중첩 표본 수가 충분해지기 전에는 챔피언/실주문 변경 금지.
- 판정 알림 `r12-s1-price-oos-v1`: 2026-09-28 이후 두 선택 종목 목록이 다른 비중첩 h20 블록만 사전 선택한다. 성숙 블록 12/24/36/48개에서만 판단하고 각 look의 **처음 N개**만 사용한다(누락 블록을 유리한 후속 블록으로 대체하지 않음). 완료/무결성 90% 이상과 유효 12개 이상이 전제다. 비용 후 차이 평균의 고정 시드 10,000회 bootstrap 양방향 구간을 양방향×KR/US×4회 = 16개 판정으로 Bonferroni 보정한다. 하한 >0/상한 <0은 관리자 **연구 신호**일 뿐이며 섹터/베타/현금·시장국면·개별 종목 제거 민감도와 체결 검증 없이는 승격 후보가 아니다. 반복 확인에도 상시 재판정하지 않도록 look을 고정한다.

#### R12b 회사 체질 제외 필터 증분 (`r12-s1-quality-v1`, 주문 미연결)

- R12a에서 이미 동결된 **같은 가격 3팩터 상위 후보와 전진 종가**만 쓴다. 같은 세션 PIT의 `quality_points`와 `quality_evaluable`을 별도 최초 관측 스냅샷에 기록한다. 한국은 평가 가능 항목 3개 이상, 미국은 2개 이상이어야 한다. 미국의 2점과 한국의 5점을 직접 비교하지 않는다. 상위 후보 한 명이라도 분모·PIT 날짜가 누락되면 그 에피소드는 `blocked_input`으로 보존하고 유리한 후속 에피소드로 바꾸지 않는다.
- `points/evaluable >= 0.5`면 유지, 미달이면 현금으로 둔다. 컷은 관측 성과를 보고 고른 값이 아니라 ‘확인된 항목 중 절반 이상 통과’라는 **연구 전용 고정 의미론**이다. 첫 관측 후보의 통과 수·비율 분포를 관리자 화면에 함께 표시한다. 현재 이 분포로 실주문 문턱을 정했다는 뜻이 아니며, 분포·품질·증분 검증 전에는 승격 불가다. 제외 자리를 다음 순위로 채우지 않는다. 같은 수만큼 **가격순위 상위** 종목만 보유하고 나머지를 현금으로 두는 세 번째 대조군을 함께 둔다. 따라서 ① 원래 가격 바구니 대비, ② 같은 현금비중 대비 차이를 분리한다. 미국은 현재 평가 가능한 재무 항목이 적어 이 필터가 약할 수 있다.
- R12a와 같은 정수주·원금·비용·다음 거래일 종가→20번째 거래일 종가를 재사용하고, R12a 가격 수정/누락 영구 보류도 공유한다. 같은 슬롯 수라도 비싼 주식의 정수주 잔여현금은 달라질 수 있으므로, quality 바구니와 현금비중 대조군의 **실제 진입 거래금액/원금** 차이가 1%p를 넘으면 해당 블록을 보류한다. 관리자 `엔진 검증 → 회사 체질 필터 증분`과 읽기 전용 `/api/admin/research/price-quality`에서 확인한다. 원천 공시 **공개시각**을 검증한 재무 전략의 역사적 성과가 아니다. 처음 관측한 미래 표본만 다룬다.
- 판정 알림 `r12-s1-quality-oos-v1`: 2026-09-28 이후 **모든** R12a 비중첩 에피소드(quality 결손·두 정책 동일 포함)를 모집단으로 사전 선택한다. 12/24/36/48 성숙 블록 look, 첫 N개, 유효 12개 및 입력/전진 가격 커버리지 90% 이상. 두 차이의 고정 시드 bootstrap 구간을 두 비교×양방향×KR/US×4회 = 32개로 보정한다. 원래 가격 바구니와 같은 현금비중 바구니 모두에 대한 비용 후 하한 >0일 때만 **선별 연구 신호**다. 원래 대비만 양수면 `현금비중 효과만 관측`으로 분리한다. 어느 경우도 live 승격 권한이 아니며 위험·시장/섹터·원천 시각·실체결 검증이 남는다.

### S2. 리비전 × 미반영 가격 × 재무 확인

기존 `revision_price`를 확장한다. 동일 FY EPS 상향 + 업종 대비 아직 낮은 가격 반응 + 재무/공시 뒷받침을 결합한다.

- 목표가 상향만으로 매수하지 않는다. EPS·추정 인원·추정치 나이·실적 발표 전후·수정 폭을 분리한다.
- 원천 발표시각이 없더라도 신뢰 가능한 **우리의 최초 관측시각 이후**만 쓰는 prospective 실험은 설계할 수 있다. 최초 관측보다 앞선 반응을 잡았다고 주장하지 않는다.
- 발표시각과 관측시각을 모두 검증해야 하는 기존 승격 규약을 몰래 완화하지 않는다. first-observed 전략은 별도 등록·별도 모집단이다.
- 같은 FY revision만, 가격은 공통 세션에 맞춘 시장/섹터 잔차, 이미 급등·실적 임박은 별도 조건으로 평가한다.
- 무효화 조건: 관측 지연을 반영하면 효과가 사라짐, 단순 모멘텀과 중복, 애널리스트 커버리지 선택편향에 불과함.

#### R13a 최초 관측 리비전 입력 동결 (`r13-s2-first-observed-v1`)

- 기존 날짜-only 컨센서스/현재 가격을 조합해 과거 `as_of` 연구 후보를 재생하던 관리자 조회는 중단한다. 2026-09-28 이후 KR 공식 마감 1~12시간 안에 append-only 관측 원장과 **live overlay 없는** 동일 세션 원시 종가로 계산한 결과만 SQLite에 최초 1회 보존한다. 과거 날짜의 동결본이 없으면 ‘없음’이지 현재 원시 가격으로 재구성하지 않는다.
- 후보마다 **동일 회계연도(FY)의 직전·현재 EPS**와 계산 Δ의 일치, 두 관측시각·내용 해시, 같은 공식 가격 세션의 종가를 확인한다. 이 증명이 가능한 상향 후보 10종목 미만이면 동결하지 않고 이유를 남긴다. 최초 관측 수집시각은 원천 발표시각이 아니다. `source_available_at_verified=false`를 유지하며 소스 공개시각을 보증하거나 발표 직후 수익을 주장하지 않는다.
- 같은 증명된 모집단에서 `EPS 상향 순위`와 `EPS 순위−업종대비 이미 오른 가격 순위`를 따로 고정하고 상위 10%의 종목·입력 가격·섹터·FY·원천 내용 해시, 가상 원금 1억원과 당시 거래비용 가정을 저장한다. 종목 수/동률 규칙도 버전에 묶는다. 이 단계는 **판단 입력의 증명**이며 전진 수익의 채점이나 실전 전략 승격이 아니다. 다음 R13b에서 다음 접근 가능한 거래 세션부터 같은 비용·위험 조건으로 paired 채점한다.

### S3. 경제적 관계의 시차: 미국 이벤트 → 국내 연결 기업

Signal Desk가 모으는 공시·뉴스·밸류체인·양시장 가격을 조합하는 차별화 후보다.

- 공시·기업 IR에 있는 매출 의존도/고객/공급사 관계만 버전 있는 그래프로 저장한다. 유효기간·방향·근거 문장·관측시각이 없으면 투자 피처에 쓰지 않는다.
- 미국의 실적/가이던스/수주 변화가 다음 국내 세션에 전달되는지 본다. ‘테마가 같다’와 ‘실적에 연결된다’를 구분한다.
- 이벤트 강도 × 관계 노출도 × 국내 종목의 미반영 잔차를 관측한다. LLM은 관계·사건 추출을 맡고 숫자·시각·보유비중은 결정론적으로 처리한다.
- 이벤트 발생 후 실제 접근 가능한 국내 시세에서 시작한다. 이미 시초가 갭에 반영됐다면 기권도 정상이다.
- 무효화 조건: 시장/섹터 상승만으로 설명됨, 관계 없는 대조군에서도 같음, 다음 접근 가능한 가격에서는 순이익 없음.

### S4. 유동성 충격과 근본 악재 분리

- 외국인/기관 흐름·거래량·가격 충격·공시 사건을 결합해 단기 반전을 탐색한다.
- 단순 낙폭과대 물타기가 아니다. 희석·실적 하향·신용·거래정지 관련 근본 악재는 별도 분류한다.
- 수급 자료의 장중 추정/확정 시각을 고정한다. 오늘 확정된 수급으로 오늘 과거 가격에 진입하는 백테스트는 금지한다.
- 진입 시점 가격·호가·수급 관측이 쌓인 다음 연구한다. 현재로서는 S0~S2보다 후순위다.

### S5. ML은 후보 생산보다 선별·기권부터

이미 있는 `meta_entry`를 사용해 후보의 비용 후 성과를 예측하고 보정한다. 초기 모델은 제한된 피처의 regularized linear/GBDT 비교면 충분하다.

- label은 실제 전략의 세션 지평·진입·청산·비용과 일치해야 한다. 동일 날짜·동일 사건에서 나온 중복 행은 독립 표본으로 세지 않는다.
- precision 외에 net expectancy, Brier/calibration, coverage(얼마나 자주 기권하는지), tail loss를 함께 평가한다.
- 모멘텀·뉴스·LLM 요약이 같은 원천이면 3표가 아니다. `evidence_group_id`로 중복 증거를 추적한다.
- RL 자율매매·온라인 자가튜닝·다중 LLM 투표는 보류한다. 연구 자동화는 허용하되 실전 승격은 검증된 고정 artifact만 가능하다.

## 6. 목표 아키텍처: 모듈형 단일 시스템에서 시작

핵심 흐름은 `시점이 확인된 자료 → 투자 가설 → 목표 포트폴리오 → 위험 검증 → 주문 의도 → 체결 대사 → 성과·설명·알림`이다. 다음 계약을 API·연구·페이퍼·수동 실주문이 함께 읽는다.

| 계약 | 필수 내용 |
|---|---|
| `EvidenceSnapshot` | 원천/최초관측/수집/사용가능 시각, 거래소 세션, source revision, 원문 hash, 데이터 품질 |
| `AlphaProposal` | 종목·시장·가설 ID, 지평·만료·무효화 조건, 점수, 보정 여부, 증거 그룹, 전략 버전 |
| `PortfolioIntent` | 현재·목표 비중, 유지 대안, 예상 비용, 위험 변화, 현금·정수주·군집 제약, 막힌 이유 |
| `OrderIntent` | 계좌/시장/매수·매도, 수량·가격 한도, expiry, 정책 버전, idempotency key, 생성 결정 ID |
| `ExecutionEvent` | 제출·거절·부분체결·취소·UNKNOWN·대사, 실제/모의 구분, 체결 수량·가격·비용·시각 |
| `PerformanceSnapshot` | NAV 범위·통화·세션·수익 정의, 기준선 버전, 원장 품질·커버리지 |

### 성향과 추종 설정

- 하나의 alpha 후보 집합을 세 위험 프로필이 사용한다. 이는 이미 같은 후보를 보는 현행 방향을 확장하는 것이다. 세 봇의 상관된 성과를 독립 알파 세 개로 세지 않는다.
- 성향은 허용 위험·종목/군집 집중·현금·회전예산으로 정의한다. ‘안정형’이라는 이름만으로 더 안전하다고 말하지 않고 관측된 위험을 함께 표시한다.
- 사용자가 요청한 **봇 주문금액의 n% 추종**은 유지한다. 여기에 내 계좌 한도·기존 보유·미체결·최소 현금·정수주를 적용하고, 잘린 금액과 이유를 미리 보여준다.
- ‘목표비중 추종’은 향후 별도 선택지다. 기존 n% 주문 추종을 몰래 다른 의미로 바꾸지 않는다. 봇에 없는 기존 보유를 자동 매도해서 비중을 맞추지 않는다.
- 일일 매수금액 한도와 회전 한도는 단위·초기화 세션을 분리한다. 매도대금을 당일 매수 한도로 자동 환급할지 여부도 명시한다.

### 프로세스와 저장소

1. 먼저 API 안의 도메인 로직을 순수 서비스로 분리한다. 기존 URL·DTO를 유지하고 characterization test로 동작을 고정한다.
2. 계좌×시장 주문 쓰기는 한 경로로 직렬화한다. 프로세스 lease와 주문 단위 transaction/idempotency는 별개다.
3. 데이터 수집·연구 작업·알림 전송은 실행 주기와 장애 영향을 분리한다. 비싼 연구가 시세/주문 처리를 지연시키지 않게 한다.
4. 처음에는 명확한 단일 writer와 SQLite를 유지할 수 있다. 여러 서버가 동시 실행하거나 별도 worker가 주문 DB에 쓰게 된다면 그 전에 Postgres의 원자적 claim/트랜잭션으로 이동한다. 공유 SQLite 파일을 서비스 여러 개에 붙이는 방식은 피한다.
5. 연구 스냅샷은 immutable Parquet + manifest로 보관하고 필요하면 DuckDB를 분석 프로세스에 쓴다. 90일 advisor hot history와 장기 검증 archive를 분리한다.
6. FastAPI는 조회·사용자 설정 중심, 주문 coordinator는 짧고 결정론적, 연구 job은 비동기 결과 조회 구조로 나눈다. Kafka/Kubernetes는 현재 필수 조건이 아니다.
7. 웹은 토큰·라우팅을 유지하며 API client, 상태 모델, 차트, 주문 미리보기, 관리자 연구 패널을 순차 추출한다. 프레임워크 변경보다 화면 간 같은 수치·같은 상태가 먼저다.

## 7. 검증 구조: 빨리 고칠 것과 오래 관측할 것을 구분

실행 결함 수정에 알파 유의성 검정을 기다릴 필요는 없다. 반대로 코드 테스트가 통과했다고 새 전략의 수익성이 입증되지는 않는다.

### 공학 검증

- 모든 매수 경로 × halt 종류 × 시장 × 손실/현금/집중/노출 제약의 회귀·속성 테스트.
- 휴장, 조기마감, DST, 서버 UTC 자정, KR/US 세션 변경, stale quote 시험.
- 동시 fast/slow 실행, 주문 전후 종료, 네트워크 응답 불명, 부분체결, 수동 외부 주문, 재시작 대사 시험.
- 미래 데이터를 붙이거나 지워도 시점 t의 피처/판정이 바뀌지 않는 검사. EMA 등 warmup 길이 변화는 허용 오차와 주문 영향으로 검사한다.
- 동일 입력/버전/이벤트 순서에서는 research·paper가 같은 목표와 주문 의도를 만든다. 실제 fill은 브로커에 따라 달라질 수 있으므로 가격까지 같다고 요구하지 않는다.

### 경제적 검증

- 고정 champion과 challenger를 **같은 시작 자산·세션·유니버스·비용·위험예산**으로 비교한다.
- 대조군: 현재 결정론적 가격전략, LLM 없는 동일 정책, 현 보유 유지, 현금, 시장 추종 대안, 제약형 동일가중. 질문에 맞는 대조군을 사전 선택한다.
- 순수익/NAV·상대성과·낙폭·tail loss·회전·현금·체결률·비용을 함께 본다. 고수익이 더 높은 위험에서 왔는지 분해한다.
- 일반 비용과 2배 비용, 지연 진입, 갭, 미체결/부분체결을 시험한다. 2배 비용은 스트레스 가정이지 실제 시장충격 측정값이 아니다.
- 신호 지평을 반영한 purged walk-forward, 날짜/사건 cluster 추론, 변경하지 않은 holdout을 사용한다. 마지막 기간을 보고 고친 모델에 같은 holdout을 다시 주지 않는다.
- 기존 사전등록·Šidák·DSR을 재사용한다. 새 가설 family·탐색 trial·코드·데이터 버전을 등록하고, 실패 실험도 보존한다. DSR 통과가 PIT 오류나 잘못된 비용을 구제하지 않는다.
- 승격 기준: 데이터·재현·위험 제약 통과 후, **사전에 정한 경제적 최소 개선폭과 다중검정 보정된 통계 요건**을 충족할 것. 이번 진단 수치에 맞춰 문턱을 고르지 않는다. 위험 완화 목적이면 비열등 수익 허용폭과 위험 개선폭을 별도 등록한다.
- ‘관측 가능 예상일’과 ‘통과/실전 적용일’을 구분한다. 화면의 120일 또는 특정 날짜 도달만으로 성향 우열·알파를 인정하지 않는다.

### 성과 분해 실험

같은 종목선정에서 (a) 신호 지평까지 유지, (b) 현재 청산, (c) 비용 인지 청산을 비교한다. 다시 같은 청산에서 (a) 고정 비중, (b) 현재 vol sizing, (c) 포트폴리오 위험배분을 비교한다. LLM 유무는 별도 축이다. 한꺼번에 전부 바꾸지 않는다.

이 비교는 설명을 위한 대조 실험이지 각 효과를 단순 합하면 전체 수익이 된다는 인과 주장도 아니다. 상호작용은 별도로 보고한다.

## 8. 사용성: 자주 거래하게 하지 말고, 확인할 이유를 만든다

### 홈을 ‘오늘의 투자 상태’로

현행 Ink Desk/teal 토큰을 유지한다. 탭·카드를 더 추가하기보다 첫 화면에서 다음 순서로 답한다.

1. **현재 상태**: 실제/페이퍼/연구 구분, 계좌 연결·가격 기준시각·선택 성향·추종비율.
2. **오늘 달라진 것**: 기존 보유의 가설 변화, 위험 한도 접근, 새 후보가 기존 보유보다 유리한 이유. 변화 없음도 한 줄로 종료.
3. **내 행동**: 유지/검토/축소/입력 보완. 종목 수익 전망보다 내 포트폴리오의 전후 변화를 먼저 보여준다.
4. **성과**: 선택 기간 누적수익 선 + 비교선, 아래 낙폭, 거래 이벤트 마커. 일별 손익 캘린더와 비용·섹터 기여도를 보조 화면으로 제공한다.
5. **다음 확인 조건**: 가격 몇 원, 공시 사건, 실적 일정, 데이터 갱신 등 무엇이 바뀌어야 판단이 달라지는지.

행동 카드의 필수 필드: `무엇/왜 지금/유효기간/내 현재→제안 비중/한도 적용 금액/핵심 근거/반대 근거/무효화 조건/아무것도 안 하면`. 수익확률이 미보정이면 ‘자료 충분도’나 ‘신호 강도’와 분리해 표시한다.

운영 UI에서 보이는 ‘매수 1.6점·손절 -7%’ 같은 고정 문구가 rank 모드·종목별 sigma 적용과 어긋나지 않게, 설명도 실제 적용 `policy_snapshot`에서 생성한다. 차트는 KRW와 USD를 합치지 않고, holdings-only일 때 계좌 누적수익 차트로 위장하지 않는다.

### Telegram을 개인 투자 요약 창으로

- 앱에서 선택한 성향·시장·알림 종류와 연결한다. 공통 `TELEGRAM_CHAT_ID` 방송에는 개인 보유·계좌 정보를 보내지 않는다.
- 1회용 만료 연결코드 + 앱 로그인 확인으로 chat-user를 묶고, 수신자별 권한·재시도·해제를 지원한다.
- 즉시 알림: 확인된 체결, 한도/주문 불명 상태, 보유 투자 가설의 중대한 무효화. 같은 상태 반복은 묶는다.
- 장 마감 요약: 내 손익/기준선/주요 기여/비용/미해결 상태/내일 확인 조건. 주간에는 거래하지 않아 지킨 비용과 놓친 기회도 균형 있게 표시한다.
- 읽기 전용 `/status`, `/why 종목`, `/performance`, `/next`를 우선한다. 주문·한도 증액은 Telegram 한 줄 명령으로 처리하지 않고 인증된 앱 확인으로 연결한다.
- Telegram 도착시각과 이벤트 발생시각·가격시각을 구분한다. 늦게 온 매수 알림은 새 매수 권고처럼 보이지 않게 만료 처리한다.
- 목표 KPI는 반복 접속 수가 아니라 행동 이유 이해도·알림 유용성·오경보·중복·누락·실행 상태 문의 감소다. D7 현재 6명 코호트로 유의미한 제품 실험 결론을 내리지 않는다.

## 9. 비용 구조: 모델 등급보다 가치 없는 반복을 없앤다

현재 추정비용에서 advisor가 약 95%다. 먼저 같은 입력을 반복 평가하는 이유를 측정해야 한다. 사용자 의도 없이 상위 모델을 일괄 저가 모델로 바꾸는 것은 해결책이 아니다.

| 작업 | 실행 조건 | 비용·지연 정책 |
|---|---|---|
| 시세·위험·주문 검사 | 거래 세션/새 시세/계좌 상태 변화 | 결정론적, LLM 호출 없음 |
| 공시·뉴스 구조화 | 처음 본 원문 또는 실제 수정본 | 문서 hash 중복 제거, 구조화 schema, 근거 인용 검증 |
| 투자 가설 자문 | 후보·근거·시장 맥락의 의미 있는 변화 | 입력 hash + 만료 cache, 동일 공용 분석 공유 |
| 고급 모델 재검토 | 근거 충돌·중요 사건·기존 모델 기권 | 고급 모델 집중 사용, 오류/무응답이면 임의 추측 금지 |
| 설명·일간 요약 | 사용자 요청/정해진 요약 시점 | 검증된 결정 객체에서 생성, 분석 재실행과 분리 |
| 연구 학습·재생 | 별도 job | 요청당 자원·시간 제한, UI/주문 경로와 격리 |

캐시 키에는 입력 원문뿐 아니라 데이터·전략·프롬프트·모델·정책 버전을 포함한다. 계좌별 제한을 가진 결정을 다른 사용자에게 그대로 재사용하지 않는다. 만료·새 악재를 무시하는 캐시는 금지다.

운영 지표는 전체 토큰보다 `새 증거 1건당 비용`, `실제로 달라진 결정 1건당 비용`, `동일 입력 재호출 비율`, `자문 증분성과`, `호출 실패/기권률`, `p95 결정 지연`이다. 월비용 예산은 기존 설정을 유지하면서 데이터/인프라를 합산해 다시 산정한다. 월 절감액·수익 증가율을 지금 확정하지 않는다.

### R10 개인 텔레그램 1차 구현 경계 (2026-09-27)

## 12. 다음 실행의 시작점
