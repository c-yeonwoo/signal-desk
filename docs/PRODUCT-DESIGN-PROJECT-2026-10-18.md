# Signal Desk 제품 디자인 프로젝트

2026-10-18 소유자 승인으로 엔진 연구와 별도 프로젝트로 관리한다. 이번 문서는 프로젝트 설정과 실행 범위이며 새 UI 구현·화면 검수 완료가 아니다. 기존 통합 로드맵40%를 유지하고 아래6개 작업의 완료 증거를 별도 집계한다.

## 목표

사용자가 ‘시장은 어떤 상태인지 → 내 관심/보유 종목을 왜 확인해야 하는지 → 다음에 무엇을 확인할지’를 자연스럽게 이어서 이해하는 투자 작업대를 만든다. 가격·근거의 시각, 확인한 사실과 추정, 신규 후보와 보유 대응을 구별해서 읽을 수 있어야 한다. 디자인의 성과는 이해·탐색·오류 예방·실측 로딩이며 투자 수익으로 주장하지 않는다.

주 사용자는 직접 피드백을 주는 소유자다. 외부5명 평가나 새 장 관측을 화면 개선의 시작 조건으로 추가하지 않는다. 화면 의미를 확정할 때 기존 사용자 피드백을 먼저 적용한다.

## 기존 작업의 계승

- [10월16일 개선안](SIGNAL-DESK-WEB-DESIGN-REVIEW-2026-10-16.md)의 D1–D6 구현 이력은 완료 이력으로 남긴다. 이후 소유자의 D7 피드백과 #744·#748 등의 후속 변경을 현재 main과 대조한다. 완료된 탭·토큰·계좌 통합을 다시 만드는 작업을 등록하지 않는다.
- 현재 상단은 오늘·종목·내 투자·관리자, 종목 하위는 국내·해외·관심종목이다. 별도 관심 메뉴·인사이트 메뉴의 재신설을 기본안으로 삼지 않는다.
- `DESIGN.md`의 과거 teal/단일 파일 설명과 실제 `design-tokens.css`의 indigo/분리 파일은 충돌한다. 이는 문서 기준선의 미해결 항목이다. 프로젝트 설정을 이유로 색상이나 메뉴를 바로 바꾸지 않는다. 첫 작업에서 실제 구현·의도·소유자 피드백을 대조해 기준을 확정한다.
- 현재 운영 화면을 이번 턴에서 새로 관찰하거나 성능을 측정한 것은 아니다. 과거 문서의 스크린샷/수치를 현재 화면의 실측이라고 인용하지 않는다. 현행 기준은 시작 시의 main SHA·경로·화면 상태로 기록한다.

## 독립 관리와 연결

같은 Paperclip SIG 회사 안에 **Signal Desk · 제품 디자인** 프로젝트를 별도로 둔다. 기존 **수익 개선 연구실**의 이슈·실행·보고·우선순위는 유지한다. 공통 저장소를 쓰되 구현은 `codex/design-*` 브랜치와 독립 PR로 진행하고, 엔진 PR과 한 번에 머지하지 않는다.

현재 연구용8역할·모델·일일 호출 설정·회사 잠금·연구 승인 todo manifest를 바꾸지 않는다. 새 디자인 이슈 등록이 기존 연구 자동 실행의 승인으로 해석되면 안 된다. 디자인 구현/검수의 역할과 파일·실행 범위를 고정한 뒤 필요한 작업만 호출한다. 프로젝트를 만들었다고 별도 agent가 계속 실행 중이라고 설명하지 않는다.

프론트엔드와 공통 문구를 기본 소유 범위로 둔다. API가 필요한 경우 별도 변경으로 영향과 계약부터 검수한다. 시그널 계산·순위·표본·원천 원장·주문 권한·자동매매 설정은 디자인 프로젝트의 변경 범위가 아니다. 가격 지연·근거 불일치·주문 불가 같은 중요한 상태는 해당 숫자/행동 옆에서 읽을 수 있어야 한다.

각 작업은 `설계/구현/배포 확인/수용`을 구분해 기록한다. 문서 작성·태스크 생성·CSS 줄 수는 완료 점수가 아니다. 완료는 작업별 인수 조건과 배포 증거로 집계한다. 예전 D1–D6의100%를 새 프로젝트에 가져오거나 새 프로젝트를 만들어 제품 성과가 초기화됐다고 주장하지 않는다.

## 진행 방식

1. 첫 작업은 현행 화면의 기준선 확보다. 기존 문서의 오래된 결함을 그대로 현재 결함으로 나열하지 않는다.
2. 주요 화면은 구현 전에 desktop/mobile 구성과 실제 내용·로딩/오류 상태를 확인할 수 있는 시안을 만든다. 시각 방향이 열린 부분만 소유자 피드백을 받고, 이미 확정한 제품 요구를 반복 질문하지 않는다.
3. 한 PR은 한 사용자 문제를 해결한다. 무엇이 달라졌는지 전후 화면과 짧은 설명으로 제시한다. 시안 검수는 desktop/mobile을 묶어1회, 발견한 문제를 한 번에 수정하고 확인1회로 마친다. 새로운 결함이 없는 한 미세수정 루프를 반복하지 않는다.
4. 화면 데이터의 시각·선택 상태·계좌 의미를 바꾸는 부분은 관련 경계를 검증한다. 저위험 문구/간격 변경에 구현을 그대로 복사한 테스트를 늘리지 않는다. 코드 변경은 독립 리뷰와 정확한 PR HEAD의 CI를 통과한 뒤 머지한다.
5. 개발 모델은 기본 GPT-6.1 Sol high를 권한다. 실제 데이터/주문 의미 충돌이나 큰 구조 결정을 해결할 때만 상위 모델 검토를 별도 판단한다. 매일 시황 편집에 상위 모델을 호출하는 구조는 추가하지 않는다.

Impeccable의 Operate 원칙을 계획에 적용했다. 제품 화면에서 과업의 읽는 순서, 익숙한 조작, 일관된 상태, 짧은 설명을 우선한다. 이번 프로젝트 설정은 정식 이중 에이전트 critique·접근성/성능 인증·새 시각 디자인 선정까지 수행한 것이 아니다.

## Paperclip 등록

[제품 디자인 프로젝트](http://127.0.0.1:3100/SIG/projects/8e296a64-b114-492c-b913-31ded551f30e)는 기존 연구 프로젝트와 다른 ID다. PD1은 [SIG-25](http://127.0.0.1:3100/SIG/issues/SIG-25)의 todo, PD2–PD6은 SIG-26~SIG-30의 backlog로 등록했다. 아직 디자인 agent 실행은 호출하지 않았다. 기존 연구 todo 자동 실행은 이 프로젝트를 가져가지 않는다.

시작 상태는 프로젝트 설정 완료 / 0/6이었다. 현재 [SIG-25 기준선·시안 검수](PRODUCT-DESIGN-PD1-2026-10-18.md)를 완료해 **PD1 완료1/6(16.7%)**다. PD2–PD6 구현·배포·수용은 미완료이며 시안을 운영 UI 적용으로 집계하지 않는다. 기존 통합 로드맵은 **40% 유지**한다.

[SIG-26 실제 목록·상세 적용](PRODUCT-DESIGN-PD2-2026-10-18.md)은 구현·로컬 검수와 독립 리뷰를 마쳤다. 기존 전체 차트는 보존한다. CI/머지·배포는 해당 전달 기록으로, 소유자 수용은 실제 피드백으로 별도 확인한다. 수용 전인 PD2를 완료2/6으로 올리지 않는다.

## 2026-10-18 자동 후속 승인

소유자가 완료 처리와 다음 작업의 시작을 자동화하도록 승인했다. 이후 작업은 독립 리뷰·정확한 HEAD CI·머지·운영 배포/실제 UI 검수를 모두 갖추면 소유자 응답 대기 없이 닫는다. 실제 소유자 수용과 자동 검수 완료는 별도다. SIG-26은 #795와 운영 검수 증거로 done, SIG-27은 즉시 구현 승인으로 진행 중이다. [내 보유와 계좌 PD3](PRODUCT-DESIGN-PD3-2026-10-18.md)의 배포 인계까지 마치기 전에는 완료3/6으로 세지 않는다. 최신 상태는 회사 runtime의 프로젝트/전달 기록으로 확인한다. 연구 원천 차단은 디자인을 멈추게 하지 않으며 디자인 구현을 수익 개선으로 세지 않는다.

SIG-27은 #796의 정확한 HEAD CI·머지·운영 배포와 실제 보유/분석 입력 화면 검수로 자동 완료했다. 현재 **3/6 완료**, [SIG-28 시장→종목 연결](PRODUCT-DESIGN-PD4-2026-10-18.md)을 이어서 구현·검수한다. SIG-28의 머지·배포/실제 화면 증거 전에는4/6으로 올리지 않는다. 소유자 수용과 수익성 개선을 추정하지 않으며 통합40% 유지다.
