## 3. 판단 구조: 한 점수 대신 서로 다른 질문

```text
시점 고정 입력 → 사용 가능한 특성
                    ├─ 시장 공통 위험·노출 맥락
                    ├─ 같은 날 종목 간 상대 전망
                    └─ 사건의 새 정보·이미 일어난 반응
                              ↓
                현재 가격에서 비용 후 추가 가치가 있는가?
                              ↓
           미보유: ENTER / WAIT · 보유: HOLD / REDUCE / EXIT
                              ↓
                 위험·호가·계좌·주문 안전 → 실행
```

시장 방향 설명, 종목 간 우열, 진입 타이밍을 한 가지 성공률로 합치지 않는다. 좋은 상대 후보라도 시장 전체가 하락하면 절대 손실일 수 있다. 반대로 시장 상승 덕분에 번 수익을 독립 종목 선정력이라고 하지 않는다. 사건·가격·유동성이 같은 방향을 가리킬 때만 새로운 정보가 더해지는지 비교한다. 모든 관점을 켜면 정확도가 오른다고 가정하지 않는다.

개념적 비교는 **같은 종료시점의 기대 순자산**이다. 신규 ENTER는 WAIT(현금), EXIT/REDUCE는 HOLD와 비교한다. HOLD 자체를 현재 상태 유지 대비 추가 가치라고 쓰면 정의상0이다. 신규 매수에는 진입·예상 청산 비용을, 보유에는 앞으로 발생할 비용과 위험을 적용한다. 이미 지출한 매입비용을 반복 차감하지 않는다. 매입가 회복 욕구나 높은 후보 순위가 손실 예산·유효기간·근거 훼손에 따른 청산을 취소하지 못한다. 갭/부분 체결 상태는 실제 잔고로 이어간다.

이 목적함수는 아직 추정·교정되지 않았으므로 확률이나 보장 수익으로 표시하지 않는다. 변동성 페널티·불확실성 구간·행동 문턱을 새로 넣으려면 별도 학습/보정 조건부터 고정한다. 이번 검토로 운영 점수나 기존 보유 후보를 바꾸지 않는다.

## 4. 새 엔진 대신 기존 구조를 쓰고, 무효 실험을 먼저 거른다

초안은 ‘시장/선정/효용 분리’를 새 설계처럼 제안했지만 기존 코드와 대조해 중복임을 정정했다. **기존 분리 후보 v2/210경로를 유지**하고 새 후보를 이번에 추가하지 않는다. 원시 수익 R3, 기존 분리 후보, MA20 보유 갱신 진단은 서로 다른 실험이다. 셋의 학습·원천·성과 상태를 섞거나 새 문서로 재등록하지 않는다.

### 실제 정량 반박과 controller 판단

Paperclip [SIG-23](http://127.0.0.1:3100/SIG/issues/SIG-23)의 성공 실행은 `d453ee89-c26d-4146-841b-7cfb4f95341e`, 본인 보고 개정은 `8656db02-dee9-4e7c-9c70-45a52196fc62`, 본문 SHA는 `f2010886d9c364e67a4f96c489d016472e7205655184e9c5fb4ab7d59cb11399`다. 실제 작성자·성공 run·개정·activity를 승인 todo controller가 검수했다. 원 초안 SHA `bc779dae7053b14039725c75a532a5d01a5283d8ebd228c765fd34fe3d9763a8`와 본문은 회사 runtime의 `missions/engine-net-utility-2026-10-18/proposal-and-critique.json`에 보존했다. 이 최종 문서는 그 반박과 기존 구현 대조를 반영한 controller 수정본이다.

수용한 지적은 다음 세 가지다.

1. 같은 날 동일한 시장 공통항·고정비용을 빼도 종목 순위와 횡단면 IC는 변하지 않는다. 시장20일 특성도 같은 날 모든 종목에 동일한 가산항이므로 그 자체가 순위를 왜곡했다는 주장은 하지 않는다. 날짜별 중심화 후 재학습은 계수를 바꿀 수 있지만 성능 개선을 보장하지 않는다.
2. 진입과 보유의 목적을 같은 미래 종료시점에서 비교하고 비용을 대칭 처리해야 한다. 이미 있는 `choose`의 개념을 재구현하지 않는다. 비용 절감과 유지된 위험 노출을 구별한다.
3. 일괄 결손 목록은 원천 인증이 아니다. 주식수 불변인 현금배당·권리 사건, 정정과 보유자별 영향을 별도로 다뤄야 한다.

반대로 정량 담당이 제안한 `kr-r3-enter-cash-devdiag-v1`은 **실험 설계 단계에서 기각**했다. 제안은 기존 R3 선정에 아래 조건만 더하는 것이었다.

```text

필요 predicted_gross > (1 + buy_cost) / (1 − sell_cost) − 1
```

기존 선정 종목이 이미 전부 통과하므로 이 필터만 붙여서는 기권도 거래도 바뀌지 않는다. Decimal 산술로 확인했고 **학습·예측·백테스트를 추가 실행하지 않았다.** 중복 필터의 구조적 무효 판정이며 전략 경제성이나 시장 기회가 없다는 판정이 아니다. 에이전트의 ready 보고도 controller 검토 없이 코드로 채택하지 않는다.

### 기존 엔진에서 점검할 실질적인 개선 지점

- **예측 여유가 실제로 있었는가:** 기존 예측과 같은 지평의 관측 결과를 붙여 보정 잔차·순위 IC·비용 후 효용을 분리한다. 원시 R3는1.25% 예상 문턱이 있는데도 스트레스에서 실패했으므로 ‘비용 문턱이 없어서’로 단정하면 안 된다. 실제 과대예측·국면별 오차·손실 꼬리는 아직 측정해 구별해야 한다.
- **비용의 현실성:** 거래대금·변동성·주문 크기에 따른 비용 차이를 별도 진단한다. 현재 호가를 과거에 넣지 않고, 관측 비용과 가정 비용을 구분한다. 기존75/120bp 계약을 바꾸지 않는다. 추후 다른 모형은 미리 고정한 ID·근거로 비교한다.
- **평균만으로 충분한가:** 기존 v2의 평균 편향 보정은 확률이나 손실 구간이 아니다. 시간순 미학습 잔차의 하방·보정 안정성을 보고, 자료가 충분할 때만 분포/하방 위험 보정을 별도 후보로 제안한다. 지금 새 분위모형·LLM 신뢰 점수·손절 문턱을 추가하지 않는다.
- **기여를 식별할 수 있는가:** 기존210경로의 대조군과 잠금을 유지한다. 시장 효과·상대 선정·비용·보유 노출·미체결 변화가 각각 어디서 나오는지 기존 원장과 연결한다. 장중 타이밍은 별도 분봉/호가 자료의 문제다.

첫 실제 실행 목표는 새 알고리즘 수를 늘리는 것이 아니라 **기존 후보를 같은 자료/계약으로 끝까지 비교할 수 있게 만드는 것**이다. 불완전 원천에서 신호 품질의 제한적 진단은 가능하지만 이를 전체 계좌 성과·총수익 인증으로 확장하지 않는다.

## 5. 개별 공시 조사의 대체: 한 번의 일괄 사전 진단

새 API 호출 전에 보존 가격·메타·검수 원장만 사용한다. 원천 전수 인증이나 수익성 재생이 아니라 **다음 실행을 막을 결손 전체 목록**을 만드는 작업이다.

### 이번에 실제로 한 번 집계한 결과

추가 원천 요청·예측·학습·전략 재생 없이, 기존 `features_at`과 원계약 입력·실제 보완 검수12키를 사용해 **현재 두 연구 기간119판단일**의 실제 가격 소비22,922종목일을 한 번 조사했다. 관측된 주식수 변동 키233개 중 검수 원장에 연결된 것은12개이고, 미검수는 **80종목·221키**다. 모든119판단일의 특성 소비 이력에 최소1개 미검수 변동이 있었다. 각 키의 소비 판단일도 따로 저장했다. 이 숫자는 주식수 변화의 원인이나 손익 오류221건을 입증한 것이 아니다.

12.604186초의 오프라인 일회 집계다. 로컬 보존물 `data/research/kr-r3-consumed-feature-share-change-inventory-2026-10-18-v1.json`은1,817,346바이트, SHA256 `eb542ddc2a1cba9a2c3477b4456ab5bda2698ae32196a9275a5e0a5e3efa2afd`다. 35개 입력과 보완 사전커밋·원문 검증을 통과한 뒤 집계했고, `fit_calls/predict_calls/strategy_replay_calls/source_requests`는 모두0이다. 재사용 가능한 일괄 진단 CLI를 구현한 것은 아니며 이번 controller 진단 산출물이다.

이 조사로 **원문 한 건 해결 후 같은 실행을 반복하는 방식이 비효율적**이라는 근거를 확보했다. 다음 개별 기업 원천 호출은 시작하지 않는다. 이 목록은 현재 두 기간의 가격 특성 이력만 포함하며, 기존7개 개발 기간 전체·일별 배당·장중 호가·모든 권리·모든 보유/주문 경로를 전수 조사했다는 뜻은 아니다. 과거 상장주식수 변화가 가격 조정을 뜻하는지, 소각/희석처럼 기존 주주의 수량을 바꾸지 않는지는 각 사건 원장으로 별도 확인해야 한다.

- 원계약 입력과 코드 해시·기간·당일 유니버스·기존 특성 결측 규약을 고정한다. 특성/시장 중위 계산에 실제 쓰인253종가, MA20, 주문/보유 평가의 소비 범위를 각각 기록한다. 최종 당첨 종목만 남기지 않는다.
- 정확한 `(종목 식별자, 이전 세션, 변동 세션)`으로 중복을 합치되, 영향을 받는 판단일·특성·보유 경로는 연결해 둔다. 미래 사건을 이전 판단의 검증 입력으로 끌어오지 않는다.
- 분류는 **검수된 보유자 영향 불변 / 가격·수량 조정 / 현금·권리 정산 / 거래정지·심볼 / 아직 모름**으로 한다. 상장주식수 증감만으로 유형을 추론·승인하지 않는다. 다른 날짜의 소각이 확인됐다는 이유로 같은 회사 전 기간을 통과시키지 않는다.
- 각 유형의 대표 양성 사례와 가격 조정·단주·조건부 권리·정정 등 경계 사례로 파서를 검수한다. **대표 파서 검수는 표본**, 전체 키의 원장 대사와 전략 평가는 전체 범위다. 예외만 사람이 확인한다. 실제 원문 데이터는 각 키에 여전히 필요하다.
- 목록에서 먼저 자료 커버리지와 처리 구현의 비용·효과를 산정한다. 원장 처리나 자료 확보 범위를 승인하기 전 개별 사건을 하나씩 해결→같은 백테스트 재실행하는 루프를 시작하지 않는다.
- 새 연구는 단순 선정 신호 진단과 권리 정산을 포함한 계좌 성과를 분리한다. 불완전한 원장에서도 이미 확인된 후보 실패는 보존하되, 사건 있는 종목을 사후 제거한 결과를 전체 전략 수익으로 쓰지 않는다. 지표에 직접 영향을 준 미확인 단위는 계속 차단한다.

## 6. 학습·평가와 중단 조건

- 시간순 train→calibration→evaluation. 라벨 청산일이 경계를 넘는 행은 purge하고 전처리도 train에서만 추정한다. 날짜 동일가중·날짜 블록 오차를 사용하고 종목일22,000개를 독립22,000표본으로 세지 않는다.
- 이미 열람한 기간은 개발/역사 검증이라고 표시한다. 새 이름으로 바꿔 독립 OOS라 부르지 않는다. 보호된 등록 헤드라인의 표본은 새 후보 튜닝에 사용하지 않는다.
- 단순 기준선·기존 정책·새 진입 후보를 같은 시각·위험 예산·비용·체결 규약으로 비교한다. 시작 위상5개는 같은 시장 경로를 공유하므로 독립5표본이 아니다.
- 실제 완료 계좌의 비용 후 수익·낙폭·위상별 민감도·회전·진입월/종목 집중·기권률을 함께 본다. ‘적중률 상승’만으로 채택하지 않는다. 비용 감소와 수익 감소가 동시에 나오면 둘 다 보존한다.
- 결과를 보고 조건을 추가/삭제하면 새 실험으로 기록한다. 같은 자료의 반복 설계가 우연한 합격을 만들 수 있으므로 후보 수·변형·실패를 누적한다. PBO/복잡한 검정을 작은 자료에 붙여 자동 인증하는 것은 하지 않는다.
- 원천 충분/성능 실패면 기각, 원천 미흡이면 자료 제약, 성능과 안전 기준을 충족해도 제한된 연구 승격까지만 판단한다. 수익 복구·매일3%·완벽한 신호는 완료 기준이 아니다.

근거로 [AQR Trading Costs](https://www.aqr.com/Insights/Research/Working-Paper/Trading-Costs)의 주문·종목·시각별 비용 차이와 [Bailey 등 PBO 연구](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)의 반복 선택 위험을 참고했다. 해당 해외 표본의 비용이나 수익을 국내에 그대로 적용하지 않는다. 위 설계의 수익 개선은 아직 미검증이다.
