# 저장소 정리와 봇 매수 보류 · 2026-10-25

소유자가 Railway LLM 키 만료와 Volume 정리를 요청했고, 이어서 **매수 보류·보유 청산 유지**를
명시적으로 승인했다. 원천/원장 삭제나 수익성 전략 변경은 이 작업에 포함하지 않는다.

## 운영 실측 — 로컬 DB와 구분

로그인된 운영 `/api/data-health`, `/api/admin/storage-breakdown` 읽기 전용 응답:

| 항목 | 관측 |
| --- | ---: |
| 파일시스템 전체 | 921.4 MB |
| 표시 사용량 / 사용률 | 407.7 MB / 44.2% |
| 사용 가능 공간 | 약 497 MB |
| 앱 data 파일 합계 | 407,068,075 bytes |
| app.db | 383,098,880 bytes |
| DB 기존 재사용 가능 페이지 | 253,952 bytes |
| intraday_quotes 본문 | 163,954,688 bytes |
| PK 자동 인덱스 | 39,612,416 bytes |
| 동일 열의 추가 조회 인덱스 | 39,612,416 bytes |

파일시스템 숫자는 Railway 상품의 과금/할당량을 대신하지 않는다. `cache` 합계와 그 안의 파일을
다시 더하지 않는다. cache라는 이름 안에 실제 가격·사용자·판정 원장이 있으므로 통째 삭제 금지다.

## 정리 범위

1. `idx_intraday_quotes_lookup`의 실제 정의가 PK 자동 인덱스와 완전히 같을 때만 제거한다.
   열순서·정렬·collation·부분 조건·보조 열까지 검증한다. 다른 정의면 보존한다.
   가격 행과 PK는 유지하고 같은 범위 조회가 자동 인덱스를 쓰는지 회귀검사한다.
2. `advisor_prompt_cache.expires <= now`인 만료 응답만 정리한다. 활성 캐시와 판단 이벤트는
   보존한다. 새 LLM 응답이 들어올 때에만 청소하던 경로에 부팅·기존 일일 유지보수를 추가한다.
3. `storage-breakdown`은 중복 인덱스 상태, 만료/활성 캐시 수, 빈 페이지 크기를 읽기 전용으로
   보고한다. `data-health.storage_cache_cleanup`은 가장 최근 만료 캐시 삭제 건수를 표시한다.

예상 효과는 **약 39.6 MB를 DB 내부 재사용 공간으로 전환**하는 것이다. 이는 삭제된 가격이 아니라
재생성 가능한 중복 인덱스다. DB 파일이나 Railway 표시 사용량이 즉시 39.6 MB 줄어든다는 뜻이
아니다. 물리 파일 축소용 VACUUM, WAL/SHM 직접 삭제, 원본 행/연구 파일 정리는 하지 않는다.
인덱스는 원래 정의로 재생성 가능하며, 만료 프롬프트 캐시는 삭제 후 별도 복원본을 남기지 않는다.

## 키 만료 중의 매매 동작

기존 로직은 advisor 인증 실패를 `None`으로 받아 일반 매수를 점수순으로 대체할 수 있었다.
추가매수·종목 교체·예약은 advisor를 호출하지 않으므로 별도로 계속될 수 있었다.
따라서 키 만료가 전체 주문 중지를 뜻하지 않는다.

승인된 별도 스위치 `BOT_BUY_PAUSED`를 둔다. **기본값 true**, 미설정·빈 값·알 수 없는 값도
보류다. 명시적 `0/false/no/off`에서만 재개한다. 키 교체 자체로 자동 재개하지 않는다.

- 신규매수, 추가매수, 교체매수와 이를 위한 선행 교체매도, 예약매수를 보류한다.
- 예약은 실행 보류 상태로 남기며 삭제/체결 처리하지 않는다.
- 손절·익절·트레일링·사건 위험에 따른 보유 청산 경로는 유지한다.
- 미리보기에서도 보류 상태를 반환하고, 상태가 실행 정책 ID에 포함된다.
- `BOT_KILL_SWITCH`와 별개다. 긴급 전체정지가 이미 켜져 있으면 그것을 해제하지 않는다.
- 환경변수는 재시작/재배포 시 적용한다. 이미 브로커에 제출된 주문의 취소·수정은 수행하지 않는다.
- 가격 단절·휴장·정지 등 기존 주문 안전조건을 우회하지 않으므로 청산 체결을 보장하지 않는다.

`data-health.bot_buy_control`에서 매수 보류와 전체정지를 따로 확인한다. 기존 LLM 선택 상태가
활성으로 표시되더라도 이 매수 보류가 우선한다. 이 작업은 키를 복구하거나 LLM 인증을 정상으로
인증하지 않는다.

## 검증과 후속

PR #827 (`a933264`, HEAD `ff4c25057ebfc83fe3d3fba5846fd719605aa882`)는 독립 리뷰·CI 성공 뒤
머지됐고 Railway 배포 상태도 success다. 배포 후 운영 응답에서 다음을 별도로 대조했다.

- `bot_buy_control.buy_paused=true`, `all_orders_paused=false`: 승인한 매수 보류가 적용됐다.
- 만료 자문 캐시 44행 제거, 활성/만료 캐시 잔여 각각 0행.
- 중복 인덱스 없음, PK 조회 인덱스 유지. 가격 테이블 163,954,688 bytes도 그대로다.
- 내부 빈 페이지는 253,952 → 39,878,656 bytes. 실제 파일은 383,098,880 bytes로 같다.
- boot_count 500 → 501. 최근 KR/US 판단 4개 ID가 배포 전과 일치한다
  (`fd7ff2cb…`, `b3b8b344…`, `1de04d96…`, `e5131e09…`). 전 행 해시 비교를 한 것은 아니다.

즉 약 39.6 MB를 앞으로 재사용할 수 있게 했지만, 파일시스템 사용률 44.2%를 즉시 낮추지는 않았다.
가격·판정·매매 원장은 삭제하지 않았다. 만료 캐시 44행은 복원본을 남기지 않은 임시 응답이고,
제거한 중복 인덱스는 필요하면 같은 정의로 재생성할 수 있다.

중복 인덱스 제거 전후 행 동일성·PK 유일성·실제 쿼리 계획, 변형 인덱스 보존, 만료 경계,
양 시장 매수 경로 차단·보유 청산 유지·예약 보존을 오프라인으로 검증한다.
정확한 PR HEAD CI와 머지 후 운영의 인덱스 상태/빈 페이지/매수 보류 응답을 별도로 확인한다.

새 장중 엔진은 [리부트 설계](ENGINE-INTRADAY-REBOOT-2026-10-25.md)의 R1 원천 확인이 다음이다.
연속 분봉·정상 호가·비용 자료 없이 새 정책의 수익성 검증이나 실전 채택을 완료로 세지 않는다.
이번 저장소·안전장치 변경으로 통합 로드맵 점수를 올리지 않는다. **40/100 유지**.
