# Signal Desk 전문가 회사 하네스

## 목적과 현재 범위

정량·시장국면·사건수급·체결위험·원천·구현·독립검증을 분리하고, 짧은 반박 뒤 연구책임자가 다음 단일 작업을 정하는 구조다. 같은 자료 결손 확인과 문서화만 반복하는 대신 코드와 실행 가능한 비교로 연결한다. 전문가 수나 토론 횟수가 아니라 종료된 구현·기각·새로운 차단 증거를 산출물로 센다.

**회사 설치·8개 역할의 모델 연결·첫6회 토론 완료를 확인했다. 수익 향상은 아직 증명되지 않았다.** 전문 금융 스킬을 설치한 것으로 간주하지 않으며 기존 연구 잠금·운영 시그널·실주문 권한을 바꾸지 않는다. 같은 모델의 역할 분담은 서로 독립적인 시장 정보나 실제 금융 전문가를 확보한 것이 아니다.

## 운영 명령

아래 명령을 저장소 루트에서 사용한다. 런타임 폴더에도 원본 설정·실행 파일의 링크와 `installation.json`, 역할별 조율 폴더·고정 검토 자료가 있다. 설정 원본을 두 군데 복사해서 다르게 유지하지 않는다.

```bash
node ops/paperclip/provision.mjs --check
node ops/paperclip/provision.mjs --apply --enable-manual
node ops/paperclip/verify.mjs
node ops/paperclip/round.mjs --run --goal '기존 R3 선정과 판단 시각을 고정하고 보유 유지·순수량 조정의 비용 효과를 개발 진단으로 분리한다. 새 수집·운영 전략 변경·실주문은 하지 않는다.'
node ops/paperclip/round.mjs --resume STATE
```

`STATE`는 실제로 저장된 라운드 상태 경로로 바꾼다. 먼저 `--check`로 대상 회사·런타임·기존 After 격리를 확인하고, 적용 뒤 `verify`로 실제 구성을 확인한다. `--enable-manual`은 수동 토론 실행을 위한 설정이지 주기 실행이나 실주문 허가가 아니다.

## 첫 토론과 상한

```text
정량 의견 ─┐
체결위험 ──┼── 독립 3의견(동시 최대2)
시장국면 ──┘
                            ↓
                         QA 반박
                            ↓
                         정량 답변
                            ↓
                 책임자: 구현 / 기각 / 자료 차단
```

첫 토론은 총 6회, 반박·답변 1세트로 끝낸다. 활성 라운드는 한 번에 1개, 라운드 상한 7회, 동시 상한 2회, **에이전트별 일일 상한 4회**, 개별 실행 제한 600초다. 첫 라운드는 정량 2회·나머지 관련 역할 각 1회여서 기존 실행으로 상한을 소비하지 않았다면 같은 날 진행할 수 있다. 회사 전체의 일일 상한이 4회라는 뜻은 아니다. 중단되면 상태를 보존하고 `--resume`하며 완료된 호출을 다시 돌리거나 상한을 몰래 늘리지 않는다. 실패·재시도까지 기록하고 설정값과 실제 강제·검증 여부를 구분한다. 모델 실행은 기존 계정의 구독 사용량을 소비한다. 이 설정은 원화 과금 상한이나 무료·지출 0원 보장이 아니다.

첫 미션에서는 기존 R3의 강제 청산/재매수 비용 문제를 같은 선정·시각 조건에서 검토한다. 보존 7개 개발 창과 기존 순수량 실행부를 우선 사용한다. 비용·거래 차액·회전율·현금 제약의 최소 비교를 정하고, 이미 된 일은 반복하지 않는다. 토론 뒤 구현은 별도 작업으로 넘기며 첫 토론 자체를 역사 수익 개선이나 210경로 완료로 세지 않는다.

## 실행·검증 경계

회사/역할 생성 시 Paperclip의 lifecycle hello가 구독 사용량을 소비할 수 있다. 이 연결 검사는 토론6회와 별도이며 0원/0호출이라고 보고하지 않는다. 예약 실행과 할당·멘션 자동 깨우기는 계속 OFF이고, 이 서버의 `allowExplicitManualWake` 확장으로 controller가 승인된 라운드의 다음 단계를 명시 호출한다. 다른 Paperclip 버전에서는 재검증한다.

각 보고서의 정확한 revision·담당 agent·성공 run·서버 document activity를 대조한다. 프로세스 성공만으로 업무 완료를 인정하지 않는다. 같은 goal/config/base의 중복 실행, 불명확한 POST 자동 재전송, 실패 라운드의 무조건 재시도를 막는다. 설치 ID는 활성화 전에 저장하고 일부 활성화 실패 시 이 회사의 역할만 중지해 재개 증거를 보존한다.

OpenAI Docs의 [비대화형 CLI 권한 지침](https://learn.chatgpt.com/docs/non-interactive-mode)에 따라 조율 폴더에만 쓰기를 허용하고 전체 샌드박스 해제를 사용하지 않는다. Paperclip 연결에 필요한 네트워크 허용은 localhost만으로 제한된 방화벽이 아니며, 회사/폴더 분리와 환경변수 제외도 OS 수준 비밀 격리를 뜻하지 않는다. 실제 무인·거래 실행 전에는 전용 자격증명·파일/네트워크 정책이 별도로 필요하다.

오프라인 계약 검사13개와 독립 코드 리뷰를 완료했다. 리뷰에서 발견한 부분 활성화 복구 결함은 수정 후 재검토했다. 이 검사는 토론 구조/실행 경계의 검사이지 시그널 수익성 검증이 아니다.

최종 재확인에서 초기 보관 회사(`f93606a0-012d-4155-882e-b7cff6bf4e0e`)가 공용 목록에서 사라진 것을 관측했다. After·MAKELI와 Signal Desk는 그대로다. 원인·변경 주체는 이 관측만으로 판단할 수 없으므로 외부 회사 차이로 따로 보고하고 복원·수정하지 않는다. Signal Desk 자체 구성 검사는 계속 엄격하게 수행한다.
