# SIG-27 · 내 보유와 계좌의 읽는 순서

기준 main `f1904fbcd489ccab8b1a6dcedfbcacbc002a4eea`. 소유자가 즉시 구현·검수·CI·머지를 승인했다. 기존 토큰·Pretendard·메뉴·계좌/배당 동선은 유지한다. **엔진·API·주문 규칙·원천·수익성 연구는 변경하지 않는다.**

## 확인한 문제와 변경

로그인 운영 화면은 실계좌 조회 실패 상태였다. 실패 아래에 과거 진단이 먼저 나오고, 분석용 입력은 편집 폼과 종목코드가 반복되는 표부터 보였다. 계좌 조회의 HTTP 실패와 빈 보유를 혼동하거나 시장 전환 중 이전 응답이 새 화면을 덮을 여지도 코드에서 확인했다. 실제 토스 인증 실패 자체를 이번 UI 작업으로 고쳤다고 주장하지 않는다.

- 고정 순서: **시장 → 실계좌 조회 → 계좌·주문 연결 → 분석용 입력 → 새 진단 → 지난 기록·선택 도구**. 요청마다 노드를 다시 옮기지 않아 DOM/키보드 읽는 순서도 같다.
- 실계좌와 분석용 입력의 출처를 각각 표시한다. 표시 시각은 화면 조회 시각이며 증권사 시세 기준시각은 미확인이라고 밝힌다. 분석용 입력의 실제 저장·수정 시각은 기존 API가 제공하지 않아 만들어내지 않는다.
- 과거 진단과 성과는 기본 접힘. 입력 편집은 종목 수부터 읽고 펼치며, 실제 빈 입력일 때는 편집창을 연다. 종목코드 중복은 제거하고 수량·평균 매입가의 라벨과 통화를 표시한다.
- 실계좌 실패·권한 없음·실제 빈 보유를 구별한다. 재조회와 연결 상태 확인을 노출한다. 실계좌가 실패해도 분석용 입력은 별도로 읽는다. 입력 조회 실패 때 전체 교체 버튼을 잠근다.
- 현금·한도가 불명확하면 기존 값이나 0원을 넣어 진단하지 않고 보류한다. 재시도는 접힌 설정 밖에 둔다. 시장 전환과 같은 시장 재요청의 늦은 입력·계좌·성과·설정 응답을 버린다.
- 계좌 전체 수익률과 보유주식 참고 손익은 기존대로 구분한다. 금액을 모르면 `확인 필요`로 남긴다. 원화·달러를 합산하지 않는다. 비중 그림·과거 성과 차트·주문 사전점검·배당 딥링크는 제거하지 않는다.

## Direction contract

**Mode:** Operate. **Thesis:** 현재 보유의 출처를 확인한 뒤, 같은 입력으로 진단한다. **First viewport:** 현재 상태·오류·다음 행동부터. **Form:** 기존 표·네이티브 details·기존 버튼 계승, 새 브랜드/색/이미지/LLM 없음. **Finish:** bounded desktop/mobile inspection, independent review, documented provenance; existing DESIGN.md drift is not silently rewritten.
