## 문제

유니버스가 **"오늘 기준 시총 상위 200(보통주)"** 이다. 5년 백테스트가 그 목록으로 돌아가므로
2022년에 상위 200이 아니었거나 그 뒤 상장폐지된 종목이 **처음부터 없다.** 과거 모멘텀 상위를
고르는 전략은 이 편향만으로 좋아 보인다 — `CLAUDE.md`가 "연율 179%·MDD 0.0%"로 기록한 그 병이다.

대조군이 같은 편향을 공유하므로 **백분위 자체는 유효**하지만, 두 가지가 남는다.

1. **절대 수익률을 쓸 수 없다**(이미 코드 주석·문서가 그렇게 적고 있다).
2. **편향이 팩터마다 다르게 작용한다.** 이번 세션 실측: 같은 시뮬레이터에서 3팩터(사실상 모멘텀
   단독)는 백분위 **95.0**, 6팩터는 **53.5**였다. 모멘텀은 "오늘 상위 200"에서 특히 잘 나온다 —
   그 95.0의 상당 부분이 편향일 수 있는데 **지금 구조로는 그것을 가를 수 없다.**

## BACKLOG의 전제가 틀렸다 (2026-08-05 확인)

`BACKLOG.md`는 *"시점별 편입 종목을 얻으려면 pykrx 벌크 엔드포인트가 필요한데 전부 빈 응답 …
`KRX_ID`/`KRX_PW` 계정만 있으면 … **사용자 액션 필요, 미검증**"* 이라고 적고 §0에
*"진짜 편입종목 리스트는 공식 API에 없음"* 이라고 적었다.

그런데 **`ingest/krx_open_api.universe_by_marketcap(bas_dd, limit)`이 이미 날짜 파라미터를 받는다.**
내부에서 `daily_trading(basDd)` → `sto/stk_bydd_trd`("유가증권 일별매매정보", §0에 **승인 완료**로
기록)를 부르고, 그 응답은 **그 날 상장돼 있던** 종목의 시총이다. 즉 지금 폐지된 종목도 과거
날짜에는 들어 있다 — 생존편향을 없애는 데 필요한 바로 그것이다.

막힌 것은 "코스피200 **편입종목** 리스트"였고, 우리 유니버스는 애초에 **시총 상위 200 근사**라
날짜별 시총으로 재구성할 수 있다. pykrx도 KRX 계정도 필요하지 않다.

**실측 확인(사용자 실행, 2026-08-05)** — 7개 날짜 전부 200종목 반환:
`20260803` · `20260602` · `20251201` · `20250602` · `20240603` · `20230602` · `20220208`
→ **5년 전 구간이 열린다.**

부수 확인: `prices.parquet`에 이미 **710종목**이 있고 그중 **510종목은 현재 유니버스에 없다**
(거래일 길이 중위 496일). 과거에 상위 200에 들었다 빠진 종목의 시세가 상당히 쌓여 있는데
하네스가 `{오늘의 200}`으로 패널을 만들어 **510종목을 버리고 있었다.**

| 지표 | as-is | to-be |
|---|---|---|

| 상장폐지 종목 | 패널에 **없음** | 폐지 시점까지 있고, 마지막 종가로 청산 |
| 유니버스 이력 | 없음 | `universe_history.json` + `data_freshness` 등록 |
| 편입/편출 기록 | 없음 | 스냅샷별 진입·이탈 종목 수를 이력에 남김 |

**성공 기준은 편향 제거 자체다(D6).** 백분위가 오르든 내리든 성공 여부와 무관하다 —
오히려 내려갈 가능성이 높고 그게 정상이다. 성공은 셋으로 판정한다.

1. 백테스트가 **시점별 유니버스**로 돌아간다(같은 날짜에 그 날 상위 200만 후보).
2. **폐지 종목이 패널에 들어 있다**(폐지 전 구간 보유 가능, 마지막 종가로 청산).
3. **무엇이 얼마나 바뀌었는지**를 이력에 남긴다 — 스냅샷 수·총 종목 수·신규 종목 수·구간.

## 요구사항 — 기능

### F1. `universe_history.json` — 월 1회 스냅샷
`{ "YYYY-MM-DD": [{"ticker": "005930", "name": "삼성전자"}, …] }`.
날짜는 **그 달의 첫 거래일**(주말·공휴일이면 최대 5일 앞으로 탐색 — `ingest.krx.universe()`가 이미
쓰는 방식). 60개월 × 200종목이라 JSON으로 충분하다(약 1MB).

- `store.fetch_universe_history(months_back=60, force=False)` — 이미 캐시된 달은 **건너뛴다**
  (재실행이 싸야 자동 루프에 넣을 수 있다). 실패한 달은 이름과 함께 로그로 남기고 계속한다.
- **`_request`에 백오프를 넣는다.** 지금은 단발 시도이고 재시도가 없다. KIS에서 이미 배운 교훈이
  있다(`CLAUDE.md`: "짧은 간격으로 재요청하면 HTTP 403"). 콜 간 짧은 sleep + 1회 재시도.

### F2. `store.universe_at(date)` — 룩어헤드 없이 조회
그 날짜 **이하**의 가장 최근 스냅샷을 돌려준다. 없으면 `None`.
**미래 스냅샷을 절대 쓰지 않는다** — 이게 이 기능의 룩어헤드 경계이고 테스트로 박는다.

### F3. 백테스트가 시점별 유니버스로 돌아간다
`harness.scores_with_pit_fundamentals(...)`에 `universe_at: Callable[[str], set[str] | None]`을 넣는다.
그 날짜 유니버스에 없는 종목은 **점수를 내지 않는다(None)**.

`_run_phase`의 `avail` 필터가 이미 `scores[t][i] is not None`을 보므로 **제한이 자동으로 걸린다** —
PIT 재무에서 쓴 것과 같은 메커니즘이다. 대조군(`_null_distribution`)도 같은 점수 패널을 쓰므로
**라벨 치환 대조군이 같은 유니버스 제약을 공유**한다(그래야 백분위가 p-value 구실을 한다).

### F4. 폐지 종목 처리 — 코드 추가 없음, 대신 **검증**
`build_panel`은 결측을 직전 값으로 채우고 **상장 이전만 None으로 남긴다**. 그래서 폐지 후 구간은
마지막 종가가 유지되고, 보유 중 폐지된 종목의 수익률은 **마지막 종가 기준**이 된다 = D3.

다음 스냅샷에서 그 종목이 유니버스에서 빠지므로 F3에 의해 점수가 None이 되어 **재선정되지 않는다.**
즉 "폐지 시점까지 보유 → 마지막 종가로 청산 → 다음 리밸런스에 교체"가 기존 코드로 성립한다.
**우연히 맞는 것에 의존하지 않도록 테스트로 박는다**(F7).

### F5. 시세 백필 — 유니버스 합집합
PIT 유니버스에 한 번이라도 등장한 종목의 시세가 필요하다. `store.pit_universe_tickers()`가 전
스냅샷의 합집합을 내고, `fetch_prices(universe=그 목록, full=True)`로 받는다.

**절차: 유니버스 스냅샷을 먼저 받아 종목 수를 세고 보고한 뒤** 시세 백필을 돌린다. 몇 종목이
새로 필요한지 모르는 상태로 수백 종목 × 5년을 받기 시작하지 않는다.
모멘텀이 252거래일을 요구하므로 깊이는 **5년 전량**으로 간다(부분 백필은 커버리지 구멍을 만든다).

### F6. 신선도·자동 루프 등록
`data_freshness()`에 `universe_hist` 추가(stale 임계 40일 — 월 1회 갱신).
일일 루프에 `_is_stale("universe_hist")`일 때만 `fetch_universe_history()`를 부른다(N1 규칙 —
임계는 `data_freshness()` 한 곳에만 둔다). **목록에 등록하지 않으면 낡아도 화면에 안 뜬다.**

### F7. 불변식 테스트
- `universe_at`이 **미래 스냅샷을 쓰지 않는다**(룩어헤드 경계)
- 시점별 유니버스가 실제로 패널을 **제한한다**(오늘 유니버스에만 있는 종목이 과거 날짜에서 제외)
- **폐지 종목이 마지막 종가로 정산된다**(보유 중 폐지 → 그 수익률, 이후 재선정 없음)
- 스냅샷이 없는 구간은 점수를 내지 않는다(D4)
- 대조군이 **같은 유니버스 제약**을 공유한다

### F8. 이력에 무엇이 바뀌었는지 남긴다
`fetch_universe_history` 반환값과 로그에 스냅샷 수 · 총 고유 종목 수 · 스냅샷별 진입/이탈 수 ·
구간(from~to)을 낸다. `harness_runs`의 `note`에 `universe=pit(스냅샷 N개, 종목 M)`을 남긴다 —
나중에 이력을 보고 "이 판정이 어느 유니버스로 돌았나"를 알 수 있어야 한다.

## 데이터 · API 계약

**`data/cache/universe_history.json`**
```json
{ "2022-02-01": [{"ticker": "005930", "name": "삼성전자"}, "…200개"],
  "2022-03-02": ["…"] }
```

**`store.fetch_universe_history(months_back=60, force=False) -> dict`**
`{ok, snapshots, added, failed[], tickers_total, from, to, reason?}`

**`store.universe_at(date: str) -> list[dict] | None`** — 그 날짜 이하 최근 스냅샷.
**`store.pit_universe_tickers() -> list[dict]`** — 전 스냅샷 합집합(시세 백필 입력).

**CLI** `sigdesk fetch-universe-history [--months 60] [--force]` — 최초 백필·수동 갱신.

## 엣지케이스와 실패 모드

| 케이스 | 기대 동작 |
|---|---|
| 키 없음 / 서비스 미승인 | `{ok: false, reason}` + 로그. 기존 유니버스로 계속 동작(백테스트만 PIT 불가) |
| 특정 달 조회 실패 | 그 달만 건너뛰고 **이름과 함께 로그**. 나머지는 계속(배치는 항목별 격리) |
| 스냅샷이 하나도 없음 | `universe_at` → None → F3에 의해 점수 없음 → 하네스가 `표본 부족`으로 차단 |
| 요청 날짜가 첫 스냅샷보다 이전 | `None`(오늘 유니버스로 폴백하지 **않는다** — D4) |
| 폐지 종목의 시세가 없음 | 패널에 없으므로 후보에서 자동 제외. 그 종목이 유니버스에 있었다면 커버리지 경고 |
| 보유 중 유니버스 이탈(폐지 아님) | 다음 리밸런스에 재선정되지 않음(그 기간 수익률은 정상 계산) |
| 같은 달 재실행 | 캐시 hit → 콜 0. `force=True`면 덮어쓴다 |
| 우선주가 섞임 | `_is_common_share()`가 이미 걸러낸다(§0에서 확인된 동작) |
| 스냅샷 종목 수 < 200 | 그대로 저장하고 수를 로그에 남긴다(상장 종목이 적은 과거 구간일 수 있다) |

## 완료 기준

1. `sigdesk fetch-universe-history`가 60개 스냅샷을 만들고 종목 수·구간을 출력한다.
2. `store.universe_at("2024-06-03")`이 2024-06 스냅샷을 돌려주고, `"2021-01-01"`은 `None`이다.
3. `sigdesk harness --pit-fund`가 **시점별 유니버스**로 돌고, 결과의 `note`/이력에
   `universe=pit(스냅샷 N, 종목 M)`이 남는다.
4. 불변식 5개(F7)가 통과하고 전체 테스트가 통과한다(현재 833 passed 유지).
5. `data_freshness()`에 `universe_hist`가 있고 일일 루프가 stale일 때만 부른다.
6. 재백테스트 결과가 `harness_runs`에 `preregistered_id = null`로 남고 **보드는 변하지 않는다**.
7. `BACKLOG.md` §0의 "공식 API에 없음 / 미검증" 서술을 **실측 결과로 정정**한다.
