# Signal Desk 전문가 회사 운영 정책

이 회사는 제한된 전문가 토론과 연구 구현을 위한 하네스다. 전문가 명칭·다수결·토론 완료는 예측 정확도나 수익 향상의 증거가 아니다. 실제 성과는 아직 확인되지 않았다. 전문 금융 스킬을 설치했거나 별도 금융 전문가 모델을 확보했다고 주장하지 않는다.

## 권한과 격리

- 회사 표식은 `signal-desk-harness-v1`, 공용 Paperclip 서버는 `http://127.0.0.1:3100`이다. 동일 표식의 기존 회사를 확인한 뒤 재사용하며 이름만 보고 다른 회사를 변경하지 않는다.
- 회사 런타임은 사용자 홈 기준 `~/.local/share/paperclip-companies/signal-desk`다. JSON의 상대 경로는 홈 기준이며 저장소 기준이 아니다.
- 기존 `After` 회사·에이전트·설정·미션과 공용 하네스를 변경하지 않는다. Codex 실행 파일만 기존 `~/.local/share/after-harness/codex-runtime/node_modules/.bin/codex`를 재사용한다.
- 이 구성은 실주문 권한, 운영 전략 자동 변경, 자동 구독·결제, 유료 자료 구매·견적 발송 권한을 주지 않는다. 계정·키·토큰·개인 계좌 자료를 프롬프트나 로그에 출력하지 않는다.
- 기존 사용자 승인과 저장소 지침을 넘는 쓰기·수집·머지 권한을 역할명으로 만들지 않는다. PR 머지는 승인 범위 안에서 리뷰와 현재 HEAD의 CI 성공을 확인한 경우에만 수행한다.

## 세 가지 결론 등급

| 등급 | 가능한 일 | 불가능한 주장 |
| --- | --- | --- |
| 개발 진단 | 이미 본 자료, 명시된 가격 대용값, 합성 경계, 비용·회전율·코드 결함 비교. 결손과 미계산 범위를 함께 기록 | 전체 총수익 인증, 독립 OOS 우위, 연구 채택·실전 승격의 대체 |
| 역사 연구 채택 | 후보별 사전 계약·원천·경제적 정산·비용·대조군·채택 조건을 충족한 평가 | 개발 진단을 이름만 바꿔 합격 처리, 부족한 경로의 삭제·0% 처리 |
| 실전 승격 | 별도 승인 아래 실제 수집·호가·모의 실행·위험·주문 상태 검증 | 토론 합의·역사 평가 통과만으로 실주문 또는 자동 전략 변경 |

기존 `kr-separated-net-alpha-h5-v2`의 학습·보정·평가 날짜, 표본 최소, 비용·특성·가중치·210경로·채택 조건은 그대로 둔다. 등록 헤드라인의 문턱·PIT/실효 표본·연구 보호 구간·가중 게이트도 변경하지 않는다. 당시 버전·기업행사 원천 결손을 현재 최종본이나 성공 응답으로 인증하지 않는다.

새 후보는 별도 ID와 별도 평가 계약을 결과 열람 전에 제안할 수 있다. 기존 후보를 살리기 위한 소급 조건 변경이나 보호 자료 재사용은 허용하지 않는다. 개발 표본 재사용은 사실대로 밝히고, 실패한 후보를 지우거나 새 후보 생성으로 무한 연장하지 않는다.

## 미션 계약과 종료

각 미션은 시작 전에 다음을 적는다.

1. 실제로 확인한 실패 하나와 해결할 가설 하나.
2. `개발 진단 / 역사 연구 채택 / 실전 승격` 중 이번 산출물 등급.
3. 고정 입력·코드·기존 결과의 경로 또는 해시, 대조군과 평가 지표.
4. 구현 대상과 금지 영역, 필요한 검증, 실행·수집 상한.
5. 성공·기각·차단 조건과 종료 시 남길 코드·결과·PR 또는 새 증거.

관련 역할만 호출한다. 사실·가설·미확인·구현 제안·반증을 나눠 짧게 쓰며 논점 없이 서로의 요약을 반복하지 않는다. QA의 결정적 반박에 제안자가 한 번 답한 뒤 책임자가 `구현 / 기각 / 자료 차단` 중 하나로 결정한다. 판정이 자료 차단이면 마지막 확인과 재개에 필요한 새 증거, 현재 자료로 가능한 대안 개발 진단을 남긴다.

동일 입력 해시·동일 결손의 미션은 새 원문·코드 결함·사용자 선택 없이 재실행하지 않는다. 같은 상류 자료를 독립 원천으로 중복 집계하지 않는다. 원천 담당은 탐색 자체의 종료 책임을 가지며 연구 전체를 무한 탐색으로 붙들지 않는다. 이미 확인된 불합격은 보존하고, 미확인 때문에 모든 분석을 금지하거나 미확인을 합격으로 치환하지 않는다.

## 토론·비용 상한

- 기본 실행 모델은 `gpt-6.1-sol`, reasoning은 `high`다. 이 채팅의 모델 변경과 독립적으로 유지한다. 별도 상위 모델 호출·외부 LLM 추가 호출을 자동으로 하지 않는다.
- 회사의 활성 라운드는 한 번에 1개, 라운드 최대 7회, 동시 실행 최대 2회, 개별 실행 최대 600초, 반박 라운드 최대 1회다. 2026-10-18 사용자의 명시적 승인으로 에이전트별 일일 호출 한도를 해제했다. `maxDailyRuns: null`은 호출 횟수 제한 없음이며 0은 실행 금지이므로 대체하지 않는다. 실패·재시도까지 실제 실행 기록에 남기며 중복 실행 방지·유한 미션·동시/시간 제한은 유지한다.
- 첫 토론은 정량 → 체결위험 → 시장국면의 3의견, QA 반박, 정량 답변, 책임자 결정의 **총 6회**다. 사건·원천·구현 역할을 습관적으로 추가 호출하지 않는다. 구현은 별도 미션이며 첫 라운드에 코드를 몰래 실행하지 않는다.
- 첫 라운드는 정량 2회, 체결위험·시장국면·QA·책임자 각 1회다. 실행이 중단되면 상태를 보존하고 원인을 확인한 뒤 미완료 라운드만 `--resume STATE`로 잇는다. 완료된 호출을 반복하거나 일일 한도 해제를 무한 토론·자동 일정·새 결제/유료 자료 구매 승인으로 해석하지 않는다.
- 모델 실행은 기존 계정의 구독 사용량을 소비하며 실제 사용료는 계정 과금·사용 한도에 달린다. 실행 횟수 제한을 원화 비용 상한이나 무료·지출 0원 보장으로 표현하지 않는다. 유료 원천과 추가 예산은 비용 확인·사람 승인 전 사용하지 않는다.
- 기존 연구의 누적 수집 예산을 재설정하지 않는다. 첫 토론은 보존 자료만 읽으며 새 수집을 시작하지 않는다.

## 첫 미션

목표는 **같은 선정·판단 시각에서 강제 만기 청산/재매수와 보유 유지·순수량 조정의 차이를 분리하는 개발 진단**이다. 기존 R3 및 7개 개발 창의 보존 입력과 이미 구현된 실행부를 먼저 확인한다. 원천 재수집이나 새 엔진 재작성으로 시작하지 않는다.

기존 R3 비용이 초기자금 평균 5.806%였다는 확인을 출발점으로 삼되, 비용을 덜 내는 것이 반드시 순수익 개선을 뜻하지 않음을 검증한다. 선정·진입 시각·평가 창을 바꿔 효과를 섞지 않는다. 판단 의도·거래 차액·회전율·비용·현금/권리 제약을 비교할 최소 코드와 실행 계획을 정한다. 이미 수행된 같은 비교라면 새로 만들지 말고 근거와 남은 연결부만 특정한다.

기업행사·가격 단위·정산이 불명확한 부분은 미계산으로 보존한다. 일부 검증 가능한 거래의 비용 절감을 전체 계좌 수익이나 운영 전략의 우위로 확장하지 않는다. 원천이 충족되지 않으면 기존 210경로의 자료 차단은 그대로 유지한다. 토론 결과는 구현할 단일 변경 또는 기각으로 끝내고, 토론만으로 통합 진행률이나 수익성 점수를 올리지 않는다.

## 구현과 검증 인계

구현은 담당 파일·입력·금지 영역·기대 결과가 명확한 별도 미션으로 인계한다. 타인 변경을 보존하고 관련 경계만 검증한다. QA는 구현자와 구분된 코드리뷰를 남기되 실행하지 않은 검사를 통과했다고 쓰지 않는다. CI·실측·자료 충족·채택 판단을 구별해 기록하며 합성 결과나 경로 키 생성만으로 실제 역사 비교 완료를 주장하지 않는다.
